ARBITRARY-TOLERANCE AFFINE SYNTHESIS: POINT-QUERY LOWER BOUND
Date: 2026-10-08
Status: INTERNALLY-PROVED-CANDIDATE; exact oracle-model theorem only.

THEOREM

Fix rational a<b. There is no deterministic oracle algorithm that, for every arbitrary pointwise-positive function E:[a,b]->(0,infinity), uses only exact point evaluations of E, always halts, and outputs a finite affine label family satisfying the one-dimensional activity conclusion of the arbitrary-tolerance lemma.

The output family is understood to have finitely many slopes r_lambda in [a,b] and offsets b_lambda(h), with the property that whenever h_n->0, p_n->p in [a,b], and one fixed label is active at X_{h_n}(p_n) for all n, then |p-r_lambda|<E(r_lambda). The lower bound is not about a specified explicit E, a rational reaction network, a weaker finite-scale property, or an algorithm allowed additional regularity information.

PROOF

We construct oracle answers online while preserving an interval of possible counterexample points. Start with a closed interval J_0 of positive length strictly inside (a,b). When the algorithm queries E(r) at a point r already queried, answer consistently with the earlier value. For a new query r, select a closed positive-length subinterval J_n inside the current interval J_{n-1} that does not contain r. Since J_n is compact and r is outside it, dist(r,J_n)>0. Answer with any positive rational

    0 < E(r) < dist(r,J_n)/2.

The interval can always be chosen: if r lies in J_{n-1}, retain a nondegenerate subinterval on one side; if r lies outside, retain any nondegenerate subinterval. This produces a consistent partial function, and every later interval remains inside each earlier one. Thus every queried point stays a positive distance from the eventual possible-t set.

If the algorithm never halts on this transcript, the nested-interval property gives a point t in the nonempty intersection of all J_n; assigning arbitrary positive values to every unqueried argument extends the transcript to a total E. The algorithm then fails its required termination on this E.

Suppose instead that the algorithm halts after finitely many queries and outputs a finite family with slopes r_1,...,r_m. The current interval J is nondegenerate. Choose t in J distinct from every output slope. For each output slope already queried, its assigned value obeys E(r_i)<dist(r_i,J)/2, so |t-r_i|>E(r_i). For each output slope not queried, define E(r_i)=|t-r_i|/2>0. Extend E positively at every remaining point. This total E agrees with every oracle answer, but every output slope violates

    |t-r_i| < E(r_i).

For a sequence h_n->0, choose any label active at X_{h_n}(t); the minimum of finitely many affine values is attained. By finiteness, one label is active along an infinite subsequence. The activity lemma applied to p_n=t on that subsequence would require |t-r_i|<E(r_i), contradicting the construction. Therefore the halting output is not valid. In either case the algorithm fails on a total positive E extending the oracle transcript. QED.

LIMITS AND USE

The theorem shows that the arbitrary-tolerance lemma cannot be made into an always-terminating black-box synthesis algorithm using only point values of completely unrestricted E. It does not imply that any particular explicit E is unsynthesizable. In N33, the tolerance is a finite minimum built from the explicit reaction/source comparison vectors. In N50, a separate rational-family construction preserves the zero comparison hyperplanes and uses joint parameter limits to establish existence of a rational all-scale witness. Consequently this oracle lower bound is not a counterexample to N50's promised-input enumeration argument; N50 still depends on the validity of that special rational-family proof and the N33 theorem, and lacks a practical CAD implementation or complexity bound.

COST / FALSIFIER

The proof is adversarial and uses only finite rational oracle responses per finite transcript. It gives no time or query lower-bound rate. It would be falsified by a deterministic algorithm that always halts and produces a valid finite family for every pointwise-positive E under exactly this oracle interface. Adding explicit arithmetic structure, continuity/modulus promises, or permitting UNKNOWN/resource exhaustion changes the model.
