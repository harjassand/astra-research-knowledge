C02_S03: ORACLE OUTPUT LENGTH REFINEMENT
Separate implementation detail after the frozen theorem; no statement repair.
C08_S03's final REGULARIZATION_AUDIT Section2 supplies this same construction.

The case-(b) oracle may return unnecessarily long rationals. Reading their
bits is charged to A. Before moment arithmetic, clip each estimate to [0,1]
and shorten it to sufficient dyadic absolute precision. This retains the
advertised A plus polynomial postprocessing bound, without requiring a hidden
bit-length guarantee on an oracle's chosen rational denominator.

For 0<=p<=q, choose a common shift so q0=floor(q/2^r) has K leading bits
and p0=floor(p/2^r). Then
 p0/(q0+1) <= p/q <= (p0+1)/q0,
and interval width <=2/q0<=2^(2-K). If q has fewer than K bits, use the exact
ratio directly. Leading-bit extraction/comparison takes linear read work;
the subsequent rational interval and dyadic rounding use O(K) bit numbers.
Thus reading is within the oracle's charged output cost and later arithmetic
is polynomial in the requested precision rather than its verbose encoding.

Request oracle error <=zeta/[8(n+1)] and shorten with added error <=the same.
The resulting estimates meet the frozen theorem's zeta/[4(n+1)] population
guard. Clipping is nonexpansive relative to the true population in [0,1].
All Gram, Schur, matrix and final state budgets are unchanged. This is an
absolute-acquisition refinement, not a new separability promise for the
shortened estimates, a new model domain or an executed oracle experiment.
