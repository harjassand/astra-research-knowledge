# A16 Phase II, v2: finite-bandwidth audit and runnable diagnostic

Date: 2026-10-09. This append-only addendum narrows the physical claim in v1 and records the diagnostic. It does not upgrade any result to empirical validation.

## Accounting correction

The threshold must be implemented physically. Represent it as an extra fixed reference input `x_0=1`, `w_0=-theta`, so the signed current is `I=lambda V sum_{i=0}^N w_i x_i`. In every noise, power, and full-scale expression, use

    W_aug = ||w||_1 + |theta|

in place of `W`; the reference branch contributes conductance, Johnson noise, input switching/control if gated, and bias dissipation. The sensor quantization error in the digital comparator remains bounded by `2^-b ||w||_1`; using `W_aug` in the bit-width choice is conservative. The diagnostic has `theta=0`, so its numeric output is unchanged.

The noise-only `t_delta` is a lower bound on integration time, not a complete latency. A physical implementation must also satisfy its measured line/device/front-end settling floor `t_front`; therefore `t_operation >= max(t_delta,t_front)`, followed by comparator, disconnect, and reset time. The diagnostic sets an illustrative 1 ns floor. This floor is a declared parameter, not a measurement. It is included to prevent the 56 ps noise-only solution from being presented as an achievable device latency.

## Runnable diagnostic

Run from the campaign root:

    python3 work/applied/a16_physical_computation/margin_trigger_diagnostic.py

Parameters are explicitly set in the script. For `N=256`, `T=300 K`, `lambda=100 microSiemens`, `V=50 mV`, `kappa=1.5`, `gamma=0.25`, total bounded deterministic error `0.05`, `C=0.1 pF`, `sigma_read=10 aC`, and target `delta=0.01`, the exact Gaussian model gives:

    noise-only lower time                 56.22 ps
    Gaussian error at that lower time      0.01000
    300,000-sample Gaussian diagnostic     3,048 errors = 0.01016
    illustrative front-end floor           1 ns
    model error at 1 ns                     4.14e-126
    300,000 samples at 1 ns                 0 errors
    branch dissipation bound at 1 ns        0.250 fJ
    full-scale capacitor energy at 1 ns      0.125 fJ
    illustrative switches/control           7.65 fJ
    illustrative latch                       10.0 fJ
    subtotal before programming/calibration  17.? fJ

The script prints the unrounded subtotal. The zero-error sample at the bandwidth floor has no evidentiary force at `10^-126`; 300,000 samples only resolve probabilities down to roughly `10^-6`. The near-target Monte Carlo result at the noise-only time checks arithmetic for the Gaussian model, not the device.

For contrast only, the 2015 primary crossbar analysis reports an ADC benchmark of `0.85 fJ/level` at `200 kHz` (its discussion at https://pmc.ncbi.nlm.nih.gov/articles/PMC4701906/). The script multiplies that source-reported datum by 8 levels and 256 channels to print `1.7408 pJ` of ADC energy. This is not a matched baseline: it has a different date, speed, process, task, utilization, and omitted calibration/compute terms. It is included only to expose a possible component crossover scale; it cannot support a real energy or latency win.

## Consequence and exact unresolved gate

The strongest supported result remains a Gaussian-model reliability/cost equation plus a finite-control crossover test. In normalized margin classes, the ideal read-noise term can stay constant in `N`, but a complete implementation still pays `O(N)` switch and control-wire work and has `O(N)` active crosspoint volume. At fixed total conductance/power, the model does not gain latency from increasing `N`. The architecture has a real advantage only if a same-process implementation supplies values for every term and satisfies both the complete-energy inequality and latency/volume/peak-power constraints written in v1.

The exact empirical gate is a matched one-bit threshold experiment on a programmable differential array: use fixed `w`, held-out analog vectors separated by a certified margin, and record false-label rate, total input-driver plus array plus comparator plus reset energy, start-to-bit latency, active volume, calibration/write energy, and maximum power. Compare with a parallel ADC-plus-integer-tree digital implementation at identical margin/error target and sensor interface. Sweep `gamma`, `N`, and `K`; the model predicts a `mu^-2` noise-floor trend, a crossover where fixed per-input control dominates, and no free `1/N` latency at fixed total conductance. No such experiment was run in this campaign.

- Inferred from the model: the separately charged 1 ns front-end slot dominates the 56 ps noise-only time in the illustrative parameterization.
- Unverified: all chosen switch/latch/bandwidth costs and any physical energy/latency advantage.
- Novelty: unresolved. The underlying crossbar operation and idealized energy scaling are prior art; no priority claim is made for this margin-conditioned application.
