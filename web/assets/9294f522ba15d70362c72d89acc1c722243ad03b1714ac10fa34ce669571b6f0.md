# Costed single-matrix encoding of perfect matchings into c_k(F)

Worker c03_l03; revision after cross-exposure; 2026-10-07.

## Result and status

For an undirected simple graph G=(V,E) with |V|=2k, an explicit integer symmetric matrix F_G makes the single exact value c_k(F_G) contain #PM(G) in a uniquely decodable set of balanced-base digits:

    #PM(G) = 2^(-k) sum_{r in E_k} a_r,

where a_r is the centered base-B coefficient of c_k(F_G). The construction is a single-F exact encoding, but it is not a polynomial-time reduction in the ordinary binary model: the largest entry has Theta(3^(m-1) log B) bits for m=|E|. It does not establish #P-hardness or approximation-hardness under polynomial-size reductions.

Status: the encoding and cost-boundary proof is complete on paper; the executable K4 check is a finite exact diagnostic. The polynomial-bit hardness target remains unresolved.

## Construction

Order the m graph edges as e=0,...,m-1. Let

    T = binom(2k,k) (k!)^2,    B = 2T+1.

Define the 2k by 2k symmetric zero-diagonal integer matrix by

    (F_G)[u,v] = (F_G)[v,u] = B^(3^e) if {u,v}=e is an edge,
    (F_G)[u,v] = 0 otherwise.

This is one explicit matrix, and the hard onsite projection is the fixed k-pair coefficient c_k.

Since n=2k, every disjoint pair I,J of size k is an ordered cut J=V minus I, and

    c_k(F_G) = sum_{I in binom(V,k)} det(F_G[I,V minus I])^2,

with integer entries and determinants.

For each ordered cut, the Leibniz expansion indexes a determinant term by a perfect matching M of the cut graph: M is a size-k graph matching crossing that cut. Its monomial is product_{e in M} B^(3^e), with determinant sign epsilon_I(M) in {+1,-1}. Squaring and summing gives

    c_k(F_G) = sum_I sum_{M,M' in PM_I}
                  epsilon_I(M) epsilon_I(M') B^(E(M,M')),
    E(M,M') = sum_{e in E} (1_M(e)+1_M'(e)) 3^e.

Every base-3 digit of E(M,M') is 0, 1, or 2: the indicators are binary, so no carries occur in base 3. Distinct ordered edge-multiplicity vectors therefore give distinct exponents.

There are at most binom(2k,k) ordered cuts, at most k! determinant monomials per cut, and hence at most T signed monomial-pair contributions in the full expansion. After aggregation, every coefficient a_r in c_k(F_G)=sum_r a_r B^r satisfies |a_r| <= T < B/2. Repeated centered Euclidean division by odd base B uniquely recovers each a_r: take the residue q in {0,...,B-1}; replace it by q-B if q>B/2, and carry +1 to the next quotient in that case. The strict bound ensures this yields the actual signed coefficient, not only its residue.

For an exponent r=sum_e d_e 3^e, define E_k to be the set with every d_e in {0,2} and exactly k digits equal to 2. If the exponent vector of a determinant-term pair has only digits 0 and 2, then 1_M(e)=1_M'(e) for every edge, hence M=M'. Such a term is diagonal, so its sign is +1. Conversely, every graph perfect matching M crosses exactly 2^k ordered cuts: choose one endpoint of each matching edge for I, with the other endpoints constituting J. It contributes once on each cut at the unique exponent

    r_M = 2 sum_{e in M} 3^e.

Distinct matchings have distinct base-3 digit vectors. Cross terms M != M' have at least one digit 1 and cannot contribute to any r in E_k. Therefore a_(r_M)=2^k, every other coefficient indexed by E_k is zero, and

    sum_{r in E_k} a_r = 2^k #PM(G).

This proves the decoding formula.

## Cost and complexity boundary

The matrix entries are integers of bit length

    bits(B^(3^e)) = Theta(3^e log B),

so the largest entry has Theta(3^(m-1) log B) bits. Since log B=O(k log k), this is exponential in the graph input size when m=Theta(k^2), and exponential in m for any growing edge count. Writing even this one entry takes exponential time in m in the usual binary encoding. The output c_k(F_G) can have O(3^m log B) bits, and the straightforward balanced-digit decoder inspects 3^m coefficient positions. Consequently this is an exponential-bit exact encoding, not a polynomial-time many-one or parsimonious reduction. It is compatible with easy support: c_k(F_G)>0 exactly when G has a perfect matching, a polynomial-time decision predicate.

The digits are not robust to a generic relative approximation: a relative error on the full nonnegative integer does not recover the low-order centered coefficients. No approximation-preserving reduction follows.

A finite exact test is in superincreasing_pm_encoding.py. On K4, m=6, k=2, T=24, B=49; the largest matrix entry is 1365 bits, the full coefficient has 2742 bits, and balanced decoding returns 12=2^2*3. The script checks all 15 even-slot candidates and each exact coefficient. This test is diagnostic only; the argument above is the proof for arbitrary G.

## Relation to source hardness and cross-exposed peers

Valiant proves that the 0/1 permanent is #P-complete; a bipartite graph's perfect-matching count is its permanent. This supplies a named hard source, not a polynomial reduction through this construction. Primary source: Valiant, “The Complexity of Computing the Permanent,” Theoretical Computer Science 8 (1979), 189–201, DOI 10.1016/0304-3975(79)90044-6, https://www.cs.bu.edu/faculty/gacs/courses/cs535/papers/Valiant_permanent.pdf.

## Remaining gate

Find a construction whose matrix-entry bit lengths and decoding work are polynomial in the source instance, or prove a barrier for such a reduction. The present superincreasing encoding only shows how to put the count into one exact c_k value when exponential precision is paid. No universal postselected-circuit compilation, polynomial-bit #P reduction, general FPRAS, or field-level advance has been obtained.
