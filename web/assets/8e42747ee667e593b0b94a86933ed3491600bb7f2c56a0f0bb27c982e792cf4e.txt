Equal raw information: a simulation theorem for observable-basis transfer
Date: 2026-10-08
Status: exact no-new-information theorem for a named finite-state prediction
class; storage can still be a priced resource. No novelty claim.

1. Question and verdict

Can a basis learned from raw trajectories make predictions that the best
baseline retaining those same complete trajectories cannot make, on later
finite-state prediction tasks? Under the interface below, no: the raw
retainer can run the identical basis acquisition, validation, compilation,
and prediction program. It obtains the same model and can match every output
and every non-storage operation cost. This remains true under arbitrary
target drift. Deleting the raw trajectories can save the literal simulator's
retained-space charge, but a net space/time advantage over the best raw-based
strategy requires a specified time-space model and must be charged as a
resource tradeoff, not extra predictive information.

2. Exact model and task interface

Let Sigma be a finite observation alphabet. The prediction output class is
the set H_(K,b) of rational hidden-Markov predictors with at most K hidden
states. A model M consists of an initial probability vector pi, a row-
stochastic transition matrix T, emission distributions E(.|s), and a fixed
fallback distribution q_perp. Every stored rational has numerator and
denominator encodings of at most b bits. For a finite history h with positive
model probability, define D_a = diag(E(a|s)) and

    P_M(a_1...a_n) = pi D_(a_1) T D_(a_2) ... T D_(a_n) 1.

M outputs the exact next-symbol law

    q_M(a | h) = P_M(h a) / P_M(h),  a in Sigma.

When P_M(h)=0, M returns q_perp. This convention makes the predictor a total
executable map on all finite histories, including histories made possible
only by drift. A length-L forecast is the recursively specified sequence of
these next-symbol laws; if an application requests the joint law on Sigma^L,
it is computed from the same rational HMM and charged for its output size.
Exact rational arithmetic is the reference arithmetic model. An approximate
implementation is allowed only if its quantization and error are part of the
model description, output class, and cost.

Here “finite-state” means that the generated process has at most K hidden
states. Its posterior filtering vector is generally rational-valued and
history-dependent, not a bounded-bit register. All rational operations and
their bit lengths are charged. A basis/readout implementation must compile
to this named HMM class for this statement to apply; the proof does not
assert that a given observable basis always has such a compiler.

The complete source transcript R contains every raw training trajectory,
every raw validation trajectory, all source-oracle answers, and every
failed/acquisition query or branch that affected basis selection. The
transfer program and its public code are available to both methods; any
external hint, seed, or answer is included in R or charged identically.

An executable transfer procedure has three stages:

    A(R; omega_A) -> (B, candidate M, acquisition log)
    V(R_val, B, candidate M; omega_V) -> validation report v
    F(B, candidate M, v) -> final M_R in H_(K,b).

B is a finite bit string describing the acquired observable basis and its
readouts. If it cannot be serialized and compiled to a member of H_(K,b), it
is not an executable basis-transfer result in this theorem. The final model
may follow a reject/fallback branch; F and that branch are included. R_val
is part of R, whether or not it is statistically independent. All random
bits used by A, V, F, or any target-stage update routine are shared and
charged.

At later task t, the predictor receives a finite history H_t, emits
q_(M_R)(.|H_t), receives the next observation Y_t in Sigma, and updates the
HMM filtering state by its fixed forward update. A task horizon is any finite
sequence of such interactions. The environment may choose its next query or
target law using the public interaction history; it may not inspect hidden
implementation storage. The realized risk uses a declared loss
ell(q,y) in [0,1]. This interface includes one-step and recursively
multi-step prediction for the named rational-HMM output class. It does not
assert that every finite hidden-state process has a finite-state predictive
machine with at most K states.

If transfer also updates the basis or model during target tasks, that
executable update routine is part of the public protocol, must return a model
in H_(K,b), and its reads, validation, failures, and writes are included in
U_t. The fixed-model case above is the identity-update special case.

3. Matched baseline

The raw-retaining baseline receives the same R and public program. It is
required to retain the complete raw trajectories for the later-task period,
but it is otherwise unrestricted: it can preprocess once, keep any derived
cache, and use the same H_(K,b) output class and exact arithmetic. In
particular, it is not artificially restricted to relearning the basis at
each task. Call this baseline Sim_R. It runs A, V, and F on the same R and
the same random tape as transfer, then caches B and M_R alongside R. At
later tasks it runs the same HMM prediction, state update, and any public
target-stage adaptation routine.

4. Equal-information simulation theorem

Theorem. For every finite source transcript R, every executable A,V,F as
specified above, every K,b, every finite number of later tasks m, every
random tape, and every environment strategy whose choices depend only on
the public interaction history, Sim_R produces exactly the same validation
report, predictive distribution at every history, public transcript, and
conditional risk as the transfer procedure. In particular, for every
sequence of target laws (mu_t) over (H_t,Y_t), including arbitrary drift,

    Risk_t(Sim_R; mu_t) = Risk_t(transfer; mu_t),  for each t=1,...,m,

and their cumulative risks are equal. Therefore the best baseline retaining
R has risk no greater than the transfer procedure. It can also match the
transfer's source-query count, validation reads, exact bit operations,
failed searches, model writes, per-task prediction operations, and output
bits. No strict prediction, query-complexity, or computation advantage over
this baseline follows from acquiring B.

Proof. The source transcript, code, and random tape are identical, so A
returns the same B, candidate M, and acquisition log. V sees the same raw
validation trajectories and the same candidate, and therefore returns the
same report v. F consequently returns the same final rational HMM M_R and
fallback. For any initial history, both predictors evaluate the same exact
rational conditional probabilities, including the same q_perp convention
on zero-probability histories. Suppose the public interaction histories
and current model descriptions agree through task t-1. The environment
strategy then supplies the same task/query law at t. Both predictors have
consumed the same symbols and therefore have the same HMM filtering vector;
they emit the same exact distribution. Coupling any sampled output with the
same random draw gives the same next symbol and next history. If a target-
stage adaptation routine is present, it receives identical inputs and
returns the same next model and basis. Induction proves equality through all
m tasks. Equal conditional output kernels imply equal conditional and
unconditional risk under every target law, so drift does not change the
identity. Finally, Sim_R executes the same instructions in the same phases,
with the same inputs and random bits, so every non-storage operation and
query count is equal. This is a direct program simulation argument; it
assumes no benefit from the basis and no particular learning theorem.

5. Acquisition, validation, and storage costs

All charges must be reported as a resource vector before scalarization. A
minimal vector for this protocol is

    (raw/source reads and oracle calls,
     acquisition and validation bit operations,
     failed basis trials and verification calls,
     basis/model writes,
     later per-task prediction bit operations and output bits,
     retained bits or bit-time).

Let C_data(R) be the source-data generation/collection cost, which is common
to both methods and is zero when the raw trajectories are supplied as a sunk
input. Let A(R) include every basis-search/read,
fit, failed branch, exact arithmetic operation, verification step, and write
used by A. Let V(R_val,B,M) include all validation reads and operations,
including a rejection or refit branch. Let U_t(M,H_t) be the complete later
prediction/update/output cost. Then the non-storage costs of transfer and
Sim_R are exactly

    C_nonspace = C_data(R) + A(R) + V(R_val,B,M) +
                 sum_(t=1)^m U_t(M,H_t).

For a dense K-state HMM, a forward update uses O(K^2) rational
multiply-adds per observed symbol, plus emissions and normalization; a
sparse model replaces K^2 by the number of nonzero transition entries.
Recomputing a prediction from an n-symbol history costs n such updates.
The precise bit-operation cost depends on the rational numerator and
denominator sizes reached along that history and is charged in U_t for both
methods.

Thus basis acquisition and validation are not free or amortized away; they
are paid once by both the transfer and its matched simulator. Any internal
validation certificate is reproduced, not magically strengthened. A
finite empirical validation score is not itself a target-risk theorem.

For the matched simulator specifically, storage differs by construction.
Write s_R
for the bits in the complete raw transcript, s_BM for the maximum live
serialized basis/model bits over the later-task period, and s_state for live
prediction state. If transfer
discards R after validation, its later retained-space requirement is
s_BM+s_state. Sim_R, because it must retain all raw trajectories, needs
s_R+s_BM+s_state. With a charge gamma per retained bit over the later-task
period, Sim_R pays gamma*s_R more; with a charge gamma per bit per task over
m tasks, it pays gamma*m*s_R more. During acquisition, both have access to
R and both pay the same reads and working computation. If transfer also
retains R, this difference disappears. This is the exact space delta against
Sim_R, not a lower bound for every raw-retaining strategy: another baseline
might recompute from R instead of caching the basis/model and trade space for
time. If storage is not priced or the memory budget is unlimited, the delta
has no score in the stated objective. A strict advantage over the best
raw-retaining strategy requires a specific joint time-space objective or
capacity proof; it is not established here. Any such claim must also show
that s_BM fits and that drift does not make discarded trajectories useful
for refitting.

6. Risk under target drift

For fixed M and a task law mu over finite histories and next symbols, define

    R_mu(M) = E_(H,Y)~mu [ell(q_M(.|H),Y)],  0 <= ell <= 1.

The transfer and Sim_R have the same integrand for every (H,Y), so
R_mu(M) is identical for every source or target law, however the law drifts.
Use d_TV(P,Q)=sup_A |P(A)-Q(A)|. If mu_0 is the source evaluation law and
d_TV(mu_t,mu_0) <= delta_t, then the standard variational bound gives

    |R_(mu_t)(M) - R_(mu_0)(M)| <= delta_t.

If validation supplies a justified uniform certificate
|R_(mu_0)(M)-Rhat_0(M)| <= eta, then

    R_(mu_t)(M) <= Rhat_0(M) + eta + delta_t.

This last implication is conditional on the validation guarantee, on a
fixed predictor during the comparison, and on the same joint-history law
used to define mu_0 and mu_t. It can be applied conditionally after each
update if one occurs. The result here does not derive eta from finite
dependent trajectories. Without a target-drift
bound, source validation gives no nontrivial uniform target-risk bound. For
example, under binary 0-1 loss a source predictor that always emits 0 can
have risk 0 on an all-zero source law and risk 1 on an all-one target law.
Sim_R can reproduce any transfer adaptation rule included in the public
protocol that uses the later interaction, while its retained R may also
support additional updates. The simulation theorem does not require the
baseline to exploit that option.

7. What this resolves and what remains UNKNOWN

Resolved: with the same complete raw transcript, code, output class, target
inputs, and unconstrained preprocessing/cache policy, a basis learner cannot
gain new predictive information or beat the matched raw retainer on exact
outputs, later-task risk, query count, or computation. The raw baseline can
simulate the entire acquisition/validation/transfer protocol. A basis can
still be a useful compression for a separately priced storage or latency
constraint, but that claim needs a resource-constrained protocol and full
charges.

UNKNOWN: this theorem does not exhibit a task family where a learned
observable basis produces a net win under a specified RAM, retention,
latency, or preprocessing deadline after charging acquisition, validation,
and drift risk. Such a result needs a concrete basis size, a complete
same-data raw-retainer comparator, an admissible target-drift class, and a
proof that the validated basis remains adequate there. It also remains
UNKNOWN whether an adaptive observable-basis learner can provide a
certified conditioning margin for a broad finite-state process family from
the same raw trajectories. A previous project checkpoint marks that broad
acquisition question unresolved (MEMORY.md:79); no prior counterexample is
used in this proof.
