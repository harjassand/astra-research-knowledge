SU(4)/SU(5) exact finite falsification receipt
Date: 2026-10-08
Status: exact finite character/weight diagnostics only; no general theorem or
source-specific information bound is proved here.

Reproduce from the workspace root with:

  python3 outputs/research/spectral_geometry/su_m_profile/finite_falsification.py

The checker imports `exact_lr_search.py` in this directory. It counts Littlewood–
Richardson tableaux with integer recursion, computes zero-weight multiplicities
as Kostka tableau counts, and carries Casimirs and shell sums as `Fraction`s.
For each carrier it verifies the full dimension identity
  sum_nu mult(nu) dim(nu) = dim(lambda)^2.
This independent dimension checksum does not make the tableau implementation a
formal proof; it is a reproducible exact-arithmetic diagnostic.

1. Tested carriers and candidate stable window

For a regular Dynkin label tuple a=(a_1,...,a_{m-1}), put
  Delta = 1 + min_i a_i.
As an explicit diagnostic hypothesis (not an input theorem), test the proposed
stable equality
  mult(V_nu, End(V_lambda)) = dim V_nu[0] whenever C2(nu) < Delta^2.    (A)
The comparison includes every dominant nu in this Casimir ball, including
weights absent from End(V_lambda), whose multiplicity is entered as zero.

The search is exhaustive for (A): in type A,
  C2(sum_i n_i omega_i) >= (m-1)/(2m) n_i^2
for each i, since the fundamental-weight inner products are positive and
||omega_i||^2 >= (m-1)/m. The script uses this to bound every Dynkin coordinate
before enumerating labels, then tests the exact Casimir cutoff.

| Group, carrier lambda | dim carrier | End irreps | Casimir shells | labels tested below Delta^2 | discrepancies in (A) |
|---|---:|---:|---:|---:|---:|
| SU(4), (1,1,1) | 64 | 16 | 10 | 4 | 0 |
| SU(4), (2,2,2) | 729 | 76 | 33 | 19 | 0 |
| SU(4), (1,2,1) | 175 | 31 | 17 | 4 | 0 |
| SU(5), (1,1,1,1) | 1,024 | 59 | 23 | 5 | 0 |
| SU(5), (2,2,2,2) | 59,049 | 521 | 95 | 17 | 0 |
| SU(5), (3,3,3,3) | 1,048,576 | 2,131 | 208 | 55 | 0 |
| SU(5), (2,1,2,1) | 8,750 | 198 | 51 | 5 | 0 |

Within those windows the number of weights with positive zero-weight
multiplicity equaled the number with positive End multiplicity: respectively
1, 5, 1, 1, 3, 11, 1. In the min-label-one cases the strict cutoff is
vacuous apart from the trivial representation: Delta^2=4 while the first
nontrivial Casimir is m. The (2,2,2), (2,2,2,2), and (3,3,3,3) cases provide
nontrivial tests of (A). The exhaustive stable-window comparison includes
absent outputs, so it checks equality there as well as on the support.

The equality is not valid throughout the entire tensor-product support. The
first supported output, ordered by exact Casimir, for which its multiplicity
falls below the zero-weight multiplicity is:

Thus the finite data neither falsify (A) nor justify enlarging it to all
Casimirs. It also does not establish that Delta^2 is a valid universal
cutoff: only seven carriers and finite balls were tested.

2. Casimir convention and exact shell profiles

The code implements the type-A highest-weight formula
  C2(mu) = 1/2 sum_j mu_j(mu_j + m + 1 - 2j) - |mu|^2/(2m),
for the canonical GL(m) partition representative mu, corresponding to
Tr_fund(T_a T_b)=delta_ab/2 and long roots of squared length two. Exact checks
give:
  SU(4): C2(fund)=15/8, C2(adj)=4, dim(adj)=15;
  SU(5): C2(fund)=12/5, C2(adj)=5, dim(adj)=24.
In every tested carrier, the first positive shell is the adjoint shell, with
mass (m-1)(m^2-1), and therefore
  D_SU4(4)=46=1+3*15,   D_SU5(5)=97=1+4*24.
This checks the low-shell normalization and multiplicity in these examples.

Selected exact profile values (right-continuous D(T)=sum_{C2<=T} mult*dim):

* SU(4): D(0)=1, D(4)=46, D(6)=86, D(8)=356 for all three listed carriers.
  For lambda=(2,2,2), the candidate stable cutoff is 9 and D(8)=D(9)=356.
* SU(5): D(0)=1, D(5)=97, D(8)=472, D(10)=1,984 for all listed carriers.
  For lambda=(2,2,2,2), the cutoff is 9 and D(8)=D(9)=472. For
  lambda=(3,3,3,3), it is 16 and D(15)=D(16)=32,102.
* The final cumulative D equals dim(lambda)^2 in every row. The maximum
  Casimirs are 20, 60, 34 (the three SU(4) carriers) and 40, 120, 240, 75
  (the four SU(5) carriers), respectively.

Here p=|Phi^+| is 6 for SU(4), 10 for SU(5). The script evaluates ratios on
the complete continuous-T profile, not just at selected integers: since D is
right-continuous and constant between shells, a ratio with increasing
denominator is maximized at a shell-entry point (and the initial interval is
handled separately). The raw ratio D(T)/T^p has infinite supremum for T>0,
because D(T)=1 on 0<T<m. For the nontrivial part D_+(T)=D(T)-1, the exact
finite-profile maxima are:

| Group | max D_+(T)/T^p | max D_+(T)/(1+T)^p | location |
|---|---:|---:|---:|
| SU(4) | 45/4096 | 9/3125 | T=4 |
| SU(5) | 96/9765625 | 1/629856 | T=5 |

These values are identical across tested carriers of the same group because
the first adjoint shell maximizes these ratios on each finite profile. For the
full cumulative profile, max_{T>=0} D(T)/(1+T)^p=1, attained at T=0, in all
seven cases; direct shell-entry checks therefore verify the stronger
finite-carrier statement D(T)<=(1+T)^p for every T>=0. This is compatible
with the proposed fixed-m polynomial profile bound, but does not prove a
uniform estimate over all carriers. The shell tables printed by the script
include the first 12 exact (Casimir, shell mass, cumulative D) triples and the
exact last shell.

3. Scope and blockers

The finite checks find no arithmetic, LR dimension-sum, adjoint Casimir, or
candidate-window counterexample in the listed examples. They are not a proof
of the Fronsdal-Hirai multiplicity cap, its stable-range refinements, the
zero-weight growth estimate, or the D(T) exponent for all SU(m) carriers.
Those general claims require the representation-theoretic arguments and
uniform chamber estimates recorded separately in `prior_art.txt`.

This receipt addresses only finite exact conjugation-Casimir profiles. It does
not identify or test any source-specific R(Y), cap/profile hypothesis, scale
weight, or limiting operation. Any conclusion depending on those omitted
inputs remains blocked; passing these finite tests cannot validate such a
source-specific inequality or an information/channel transfer.
