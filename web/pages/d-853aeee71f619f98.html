## Exact ordinary-access inference

Let the ground set have even size n and proposed disjoint pairs
C_i={2i,2i+1}. The acquisition protocol queries all n singletons, every
C_i, and the transversal T={0,2,...,n-2}. Suppose singleton answers are
independent, pair answers dependent, and T independent. Assume the input
oracle really is the independence oracle of a matroid.

Each pair consists of two nonloops and has rank one, so its members are
parallel. Subadditivity gives r(E)<=sum_i r(C_i)=n/2. Independence of T
gives r(E)>=n/2. Every one-per-pair set has the same rank as T: replacing
one nonloop by its parallel mate preserves the rank of any set disjoint
from that pair. Equivalently, parallel elements have the same closure
relation with every remaining set. Repeating these substitutions makes
every transversal an independent set of size r(E), hence a base.

Conversely, no independent set contains both members of a pair; a base
has n/2 members, so it selects exactly one per pair. Thus the entire base
family, and not merely a tested sample of bases, is established. Its
convex hull is exactly the product of pair segments: independent choices
with marginal z_(2i) give any z with z_(2i)+z_(2i+1)=1 and 0<=z<=1 as
a convex combination of these transversals. Edges vary one pair, so the
exact edge-support bound is k=2. A rational strong optimizer compares
the two weights in every pair. Its exact minimal faces, endpoints and
the c=e0 slices used here follow from these equations and cube facets.
No additional face or slice oracle is required for this input.

The observed protocol uses n+n/2+1=38,347 independence queries at
n=25,564. The queried sets contain 63,910 ground labels in total, each
at most 15 bits, and the full query log has 1,595,573 bytes. I checked
all responses against the frozen provider's pair specification, protocol
ordering, counts, traffic and SHA256. Missing or false independent-
transversal certification is rejected. This check relies on the standard
matroid input assumption; it does not prove that an arbitrary black-box
provider satisfies the matroid axioms. The adjacent-pair hypothesis is a
successful input-specific acquisition, not a generic matroid discovery
algorithm. Every comparator receives the same acquired structure and
the same query charges.

## Exact replay identity and accounting

I compared the primary and isolated costed replay's initial state, all
movement/reset records, terminal output and control law as parsed exact
JSON objects. Each agrees exactly. The original sparse input bytes also
agree exactly. Different timing/cost fields and local input paths are the
only intentionally excluded fields. Primary input/trace, replay trace
and oracle log hashes independently match their exported reports.

The producer reports 3.2785 seconds including imports and final output
serialization, or 3.3550 seconds including its exact replay comparison;
peak process RSS is 165,003,264 bytes. Ordinary acquisition adds its
separate 0.0457 seconds including the complete query-log serialization.
Those stopwatch and RSS observations were not independently remeasured.
Our oracle/payload gate takes 0.242 seconds for reads, exact checks and
two mutations, excluding its final result serialization. The separate
trajectory checker takes 4.987 seconds, including reads and seven
rejections, also excluding final result serialization. These are separate
process costs; they are not silently included in the producer time.

Sparse input serialization/read, pair geometry, tracker moments and
control atoms use O(n) structural work here. One terminal call uses the
derived exact optimizer and 12,782 pair comparisons. The rank-two formula
avoids a dense n-by-n potential matrix, equally available to controls.
No generic dense soft filter, numerical Perron routine, conditional-
expectation engine, GLS implementation or exact-marginal extractor ran.

The producer's persistent entries have 204 bits, full exported fractions
at most 1,097 bits, and tracked Taylor intermediates at most 29,233 bits.
Its supplied 65-term fixed-degree exponential implementation and <=500-
bit exponent denominator premise admit the stated conservative 65,536-
bit canonical-entry and 131,073-bit single-product bounds. These are
fixed-fixture operation bounds and are separate from measured counters.

Our direct 120-term Taylor checker intentionally uses a different exact
certificate construction. It observes 53,712 bits in tracked Taylor
Fractions, 214,832 bits in returned measurements and 443 bits in exponent
denominators. It makes 11 cached exact exponential enclosures and 32
integer-square-root enclosures, with no dense matrix allocation. The
returned-potential denominators grow further when fourth powers combine
the rational bounds. Neither the producer's 29,233-bit counter nor its
65,536-bit conservative entry bound should be advertised as the checker's
cost. The checker counts are scoped observations, with no census of every
temporary Python integer product or independently measured peak RSS.

This gate closes the fixed-input access and replay-identity questions. It
