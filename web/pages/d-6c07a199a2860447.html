## Actual payload correction

The original oracle counter labels 72 bits per query as a payload upper
bound. This omits the explicit p argument. Eval's arguments are p,q,a,u,v.
For bit widths B_p=23,B_q=13,n=1, the correct upper bound before framing is

    (n+2)B_p+(n+1)B_q =95 bits per query,190 bits for both.

The actual integer fields contain 93 bits per query, 186 total, when leading
zero bits are omitted. Both results have a 23-bit field-width bound, so
return traffic is at most 46 bits before framing. These are integer-argument
counts, not UTF8 JSON or network-byte measurements. Pool provisioning,
parameter changes, protocol tags and framing remain additional charged
costs for a real deployment. The replay explicitly records the old 144-bit
counter and the corrected 190-bit total; no frozen label is silently adopted.
The error does not affect samples, arithmetic outputs, capacity or soundness.
