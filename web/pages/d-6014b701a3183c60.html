# DENet’s public score tables are trajectory-derived, not orthogonal function labels

**Research note — 8 October 2026.** The released DENet time courses can support forecasting selected-population abundance, but their public KRAS and MEK1 training scores do not provide an independent sequence-to-function test. I found exact identities linking every listed training score to counts from the same directed-evolution series. Consequently, a random variant split can validate reconstruction of that selection trajectory while leaving biochemical or cellular function untested.

## Exact score-to-trajectory identities

GEO deposits four snapshots each for KRAS (days 5, 9, 12, 14) and MEK1 (days 5, 7, 10, 15), with one sample accession per protein/timepoint and no deposited replicate or control series. The GEO variant tables crosswalk exactly to the integer-count files in the public DENet repository: all 8 sample genotype sets match, and all 4 MEK1 count tables match row-for-row. The terminal MEK1 sample is titled day 15 in GEO but its identical count table is named `Day20.tsv` in the code repository; I use GEO’s day-15 timestamp below.

The stronger result is an exact label identity. In `KRAS_DE.tsv`, every one of the 3,569 scores satisfies

\[
\text{score}=0.3330148018104648+\log_{10}\!\left(\frac{N_{\text{day 14}}}{N_{\text{day 5}}}\right),
\]

with the recovered offset varying by less than (1.1\times10^{-14}) across rows. In `MEK1_DE.tsv`, all 9,351 scores equal \(\log_{10}(N_{\text{day 15}})\) to floating-point precision. These are selected-population enrichment/count targets computed from the same trajectory, not separately measured protein-function values. This is consistent with GEO’s description of the files as variant abundance and with the code repository’s instruction to build co-mutation inputs from enriched variants across the evolution snapshots.

The published code’s default split is a row-level random 70/10/20 train/validation/test split. Its dataset loader shuffles genotype rows and partitions that one score table. Because the score for each genotype is an algebraic function of its day-5/day-14 or day-15 counts, and the co-mutation representation is built from those same trajectories, this split does not hold out a future selection timepoint, an independent evolution lineage, or an orthogonal function assay. Strong test correlation on these tables is therefore evidence for recovering the recorded enrichment statistic; it cannot by itself establish general sequence-to-function capability.

This is an identifiability boundary, not a claim that the DENet model is ineffective: with targets defined from selected counts, the released labels cannot distinguish a model of molecular function from a model of that selection regime’s abundance dynamics. The PNAS abstract also reports separate candidate screening; this audit does not reanalyze those experiments or dispute them.

## Prequential count-forecast check

I ran an explicit, small control on the raw snapshots. For each genotype present in the terminal table, I predicted its terminal log relative abundance from the earlier three snapshots, using (i) latest-snapshot persistence and (ii) linear extrapolation in the recorded day. I compared rank prediction with the actual chronological order, all six permutations of the three input date labels, a whole-history genotype shuffle within mutation-order classes, and 20% read-depth thinning. The variant-level values are dependent observations from a single deposited time course, so these are diagnostics, not population-level (p)-values.

For KRAS, persistence gave terminal-abundance Spearman \(\rho=0.579\); the chronological trend gave \(0.572\), with shuffled-date results spanning \(-0.129\) to \(0.572\). The 20%-depth trend retained mean \(\rho=0.516\), while shuffling whole genotype histories within mutation-order classes reduced mean \(\rho\) to \(0.169\). For MEK1, persistence was \(0.512\), the chronological trend \(0.402\), and the six date-label permutations ranged from \(0.351\) to \(0.426\). Thus genotype-specific history carries information about later abundance, but a chronological growth-trend model did not beat simple persistence in rank, and MEK1’s chronological ordering offered little advantage over permuted dates. This supports a limited abundance-forecast capability, not an independent function result.

As a leakage diagnostic, I also trained a four-input linear model on KRAS single/double-mutant rows and tested it only on the 379 score-table variants with three or more substitutions. Using the four trajectory frequencies alone gave \(\rho=0.9982\) against the held-out scores. That near-perfect result is expected from the exact score identity above; it is not evidence of biochemical extrapolation. A mutation-count-only baseline gave \(\rho=0.451\), and shuffling trajectory identities within mutation-order classes reduced mean \(\rho\) to \(0.399\).

## What would establish the distinct capability

The decisive test is prequential and assay-separated: freeze the co-mutation representation using snapshots only through time \(t\); train on function measurements from an orthogonal assay; then test on unseen high-order variants and, preferably, a held-out evolution line. Compare against terminal-frequency/enrichment-only, persistence, mutation-load, sequence-only, and order-matched genotype-shuffle baselines at the same assay budget. Repeat across independent lines and include read thinning/bottleneck controls. The pass criterion should be a reproducible gain in held-out orthogonal-function ranking or top-\(k\) hit rate over the endpoint-enrichment baseline. Until that result exists, DENet’s released score-table benchmark demonstrates recovery of selected abundance, not a separated sequence-to-function mechanism.
