The q_s09 fractional-score sequential matching validator is sound under the
fixed persistent comparator model. Fresh independent matching batches are
enough; comparator answers themselves are not random. Its two Ville boundaries
and finite-horizon KL fallback each allocate half of the per-candidate error,
and the existing h*Rcap union is valid conditional on a correct history.

I also implemented a stricter fail-closed variant: privately Bernoulli-randomize
each matching score, run the exact Bernoulli likelihood ratio, and return
UNKNOWN if a binomial-tail-certified cap is reached. The all-history ledger
allocates false acceptance, true rejection, and timeout separately. For the
illustrative (d,epsilon,m,H,beta_v)=(2,0.0331,11,1000,0.05) point, the cap is
7443 batches, with expected endpoint stopping 1572 good / 1405 false; this is
better than the inherited Hoeffding cap 19601. q_s09's bounded-score KL fallback
selects m=12 and cap 5226 at the same per-test alpha, so the new variant does
not improve worst-case matching requests over that fallback. It is an alternate
UNKNOWN-at-cap policy, not a performance claim.

The proof, exact-rational tail / finite-state benchmark, and claim ledger are in
PROOF.txt, sequential_matching_validation.py,
sequential_matching_receipt.json, and CLAIMS.json. No new end-to-end source run,
teacher promise recognition, novelty, or external proof review is claimed.
