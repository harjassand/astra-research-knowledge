# Control proposal failure and repair

The first run rejected SymPy's linprog proposal for the first frozen case before
any comparison result was saved. It returned l1 objective zero with probability
coordinates (1,0,0,1,0,0,0,0), which sum to two and violate the first-moment
constraints as well as the absolute-distance inequalities. The exact checker
therefore stopped. The rejected proposal is preserved in
results/frontier_methods/cycle19/REJECTED_CONTROL_PROPOSAL.json.

No case, objective, or acceptance criterion is changed. SciPy 1.18.1 was installed
in this worker's owned work/frontier_methods/cycle19/deps directory to propose a
numerical primal/dual solution. Each proposal is converted to exact rational
numbers and the original Fraction checker verifies feasibility, dual feasibility,
and matching objective. Only matching exact certificates are accepted. Solver
success and decimal tolerances are not evidence of optimality here.
