and produce an ordinary zero-input ILLW proof of its true Chu conclusion
without losing source-rule, premise, resource or definition obligations?

## S1: complete source validity and extension freshness

`validate_source` first checks every node's constructor, arity and earlier
children, canonical identity, and every source proof reference. It validates
the exact instantiated conclusion for each of23 source axioms and the exact
endpoint equations for MP, adj_u and necessitation. Source lines unused by
the last line are still checked. It rejects the unrestricted contraction
axiom/rule, which is not in this affine source system.

For d definitions, assign one bit to each globally distinct defined name.
The bitset of names in a syntax node is the union of its children's sets.
An ordinary source line and its annotated operands may use only already
defined names. At a defining line, its atom must be absent from all earlier
line/operand sets and its own body; the body may contain only earlier defined
names. The conclusion must be the exact equivalence conjunction. No defined
name may occur in the final rigid target. These checks imply standard
freshness and chronological acyclicity, including a dependency cycle expressed
through otherwise acyclic atom/formula syntax. An unused preallocated syntax
atom is not an earlier theorem and is correctly allowed.

This is equivalent to the stated closed fresh-EF convention. The extra operand
check adds no mathematical restriction: every required schema operand occurs
in the actual corresponding axiom formula. Empty/source-hypothesis variants
are not claimed. Work and storage for input bitsets and reading all supplied
nodes/annotations are charged; a giant unreferenced serialized graph is not
free input.

## S2: global unfold-first expansion preserves every source endpoint

Process definition bodies chronologically, redirecting an extension atom to
its already acquired body root. `expand_source` uses an iterative postorder
walk and a global old-node-to-new-node memo; it does not recursively copy
expanded trees. Freshness ensures every successful redirect points to an
earlier body. All original ordinary constructors preserve their tag and
children under the one global substitution.

At a definition, let F be its expanded body, I=`F->F`, and J=`I AND1`.
Replace it by this exact seven-line canonical source derivation:

    id(F):                         I
    adj_u(I):                      J
    fusion introduction(J,J):      J -> (J -> J*J)
    MP(J, preceding introduction):  J -> J*J
    MP(J, preceding implication):   J*J
    fusion-to-AND(I,I):             J*J -> I AND I
    MP:                            I AND I

All operands here are formulas, not additional object-level assumptions.
The reuse of the same closed J theorem is legal. Each other source step is
installed with expanded operands and with its original premise references
redirected to the corresponding replacement endpoints. The implementation
compares each resulting conclusion against the independently expanded
original conclusion, then revalidates the whole ordinary source proof.
The target is unchanged because it is extension-free.

Thus L original lines and d definitions give exactly `L_e=L+6d` ordinary
lines. If the input supplies V constructor nodes, the expansion map creates
at most V images. Beyond those images a definition adds at most5 constructors:
J, J*J, J->J*J, J->(J->J*J), and J*J->I AND I. The single unit constant costs
at most one further node globally. Therefore the expanded common node count
satisfies

    m_e <= V + 5d + 1.

The actual fixtures retain the full original-to-expanded line map and each
replacement interval. Raw extension atoms never reach the target compiler.
The cycle14 exact Łukasiewicz countermodel still blocks translating those
atoms first; the current implementation follows the valid route instead.

## S4: actual fixed-template installation, with no initial-sequent privilege

At an ordinary source axiom, bind each formal T_A/S_A to the actual acquired
Chu components of its source substitution A. At MP, bind A to the actual
first earlier source theorem and B to the actual conclusion; adj_u/Nec bind
A to their referenced theorem. Placeholders in a template are local syntax
IDs, so they cannot alias a same-named source atom. Unused formal operands
are grounded to unit1 and do not introduce a source premise.

Each used Pair input is looked up by its exact sequent in the acquired Pair
cache. Each used closed-theorem input is looked up by its exact sequent among
the source line's cited earlier installed endpoints. The input must refer
strictly before the current template interval. The implementation does not
infer an input's mathematical meaning from an arbitrary label such as
`input_3`; nonempty Pair inputs and empty theorem inputs remain distinct.

Replace those input rows by references to their acquired endpoints, then
install every remaining primitive row with its instantiated formula/principal
IDs and remapped backward premise IDs. The final installed endpoint and the
instantiated template goal must equal a freshly computed true `T_conclusion`.
The fixed template budget is at most93 added formula occurrences per step.
Finally check the entire target sequence with no named initial sequents
allowed, and compare its final endpoint with `=>T_actual_final_target`.

The composition proof is induction on source line index. Its hypotheses are
the actual prefix Pair proofs and exact earlier closed theorem endpoints;

    l_target <= 13m_e + 93L_e.

## S5: exact source, matrix, occurrence and byte accounting

The full certificate retains original/expanded source vectors, actual target
syntax and every row, the Pair prefix, input maps and accepted endpoint. It
distinguishes supplied/allocated nodes from the graph reachable by the proof's
actual formula occurrences. A supplied input with unused syntax is still read
and retained. Thus physical audit storage depends on the full supplied input
encoding plus the generated proof, not just its useful subgraph. The common
target graph has O(m_e+L_e) nodes; the actual present encoding also retains
unused supplied/raw/formal nodes, whose separate count is reported.

For every syntax node, exact unfolded formula-node count is
`n_X=1+sum n_child`. Tree bytes use a fixed reversible prefix codec: an atom
is its JSON-quoted UTF-8 name with ensure_ascii=False; a nullary constructor
is its tag; a nonnullary formula is `(tag child...)`. Its byte recurrence adds
the tag, two parentheses, one space per child, and all child bytes. Written
sequent bytes include every antecedent occurrence, commas, ` => `, the
succedent, and a newline. These recurrences count trees; they do not print
them, perform semantic simplification, or identify repeated occurrences.

With n allocated DAG nodes and maximum quoted-atom byte length b, each
unfolded tree has at most `2^n-1` nodes and at most `max(10,b)(2^n-1)` bytes.
For R target rows and l occurrences, the total sequent bytes are at most
`l max(10,b) 2^n + 8R`, because these fixed target templates have at most four
antecedent occurrences. All exact tree counts therefore have polynomial bit
length O(n+log(l+1)+log(b+1)); their addition/serialization cost is polynomial.
There are no floating values, rational denominators, optimization oracles or
unpaid numerical precision assumptions in this compiler.

An implementation audit exposed a real accounting limit: this Python runtime
rejects direct decimal conversion beyond 4,300 digits, although the integer
bit length remains polynomial in the compact graph size. `decimal_count`
therefore uses exact base-10^9 division and at most nine-digit chunk
conversions, without changing a global runtime setting. Its output has
polynomial length; ordinary integer division, chunk conversion and
concatenation have polynomial total bit cost. The bounded primitive check
retains the old conversion failure on 10^4500, verifies its exact 4,501-digit
replacement and a carry case, and recomputes the frozen certificate's byte
recurrence unchanged. It took 0.00818s. This checks the repaired accounting
primitive, not a larger whole-proof execution or a speed claim.

Source validation, definition bitsets, graph maps, template copying and
checking use polynomial bit operations in the entire supplied compact input
and pinned template size. Formula and proof references have logarithmic ID
lengths. Explicitly printing expanded trees can take exponential time/space;
it is neither executed nor hidden inside the compact output claim.
