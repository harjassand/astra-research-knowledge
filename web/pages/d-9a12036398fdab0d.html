# Metadata indexing support

Run from any directory:

```sh
python3 '/Users/harjas/Documents/ChatGPT/Literature Digestion/work/indexer/build_index.py'
```

The script uses Python 3.9+ and the standard library. It writes only `notes/INDEX.md`, `sources/INDEX.json`, and `sources/MANIFEST.json` using atomic replacement. Root has explicitly authorized those generated shared files. It never changes worker files or `NOW.md`.

It scans actual JSON, JSONL and NDJSON under `sources/`, recognizes bibliographic records in arrays and nested dictionaries, and normalizes common field aliases. Each record retains its metadata filename and JSON pointer, so original fields remain recoverable. Malformed lines, missing required fields, unusual reading depths, ambiguous or missing snapshots, and unstable hashes are reported without deleting records. Unrecognized repository/API payloads are listed separately; they do not become purportedly read sources.

The manifest hashes every regular non-hidden file under `sources/`, excluding the two generated JSON indexes, plus explicitly referenced snapshots elsewhere within this workspace. SHA-256 is streamed in 1 MiB blocks. Paths resolving outside the workspace are not followed. Snapshot references resolve against workspace root, their metadata directory, and `sources/`; distinct competing matches are reported as ambiguous. File size and modification time are compared before and after hashing to flag obvious concurrent changes.

The Markdown index presents reported title, date/version and read depth, with navigation for notes, leads and results. Machine JSON retains URL, authors, retrieval date, access status and resolved snapshots when present. The manifest identifies source bytes; it is not a backup, authenticity check, date verification, scientific validation, or universal proof. Worker-reported metadata remains worker-reported. Run again after writers finish to obtain the final inventory; multiple generated files are not a transaction across the whole workspace.

Cycle2 refresh separates access logs from bibliographic source records, supports plural snapshot paths, and labels access limitations, descriptive schema variants, and internal artifacts without external URLs. It excludes hidden files, dependency/runtime directory names, bytecode, and the current workspace's simple positive `.gitignore` patterns; it does not implement arbitrary gitignore negation semantics. Markdown navigation shows at most eight representative links per worker, preferring Markdown, while machine JSON retains the complete filtered file list. The cycle2 summary is `results/indexer/cycle2_summary.json`.

Cycle3 refresh handles `urls` maps (preferring the supplied abstract/canonical URL) and nested snapshot maps containing explicit `path` fields. All supplied snapshot formats and source versions are retained; no latest-version deduplication occurs. Internal provenance is classified using explicit metadata descriptions or local worker paths, without changing worker metadata. The cycle3 summary is `results/indexer/cycle3_summary.json`; all 962 source/snapshot manifest entries in its audited generation were independently rehashed without a difference. Descriptive reading-depth variants remain verbatim. Superseded versions are historical evidence, not implicitly current scientific claims.

Validation performed: nested metadata, field aliases, malformed JSONL recovery, GitHub payload exclusion, relative snapshot resolution, Markdown link encoding for spaces, and repeat execution excluding generated outputs. These checks used isolated temporary fixtures inside `work/indexer/`, removed after checking. Initial live execution recognized two metadata records from seven JSON files and hashed 197 local source files, with no detected metadata issues at that moment. This count is transient because workers are active.
