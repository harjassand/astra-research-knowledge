## Interface, cost, and finite precision

The N687 route is a deterministic exact-value oracle for a globally Lipschitz conservative field g=grad F, queried on chosen centers, with exact-real Gaussian seeds. It does not supply F, derivatives, VJPs, conditional means, or a mean oracle. The sampler uses k independent standard-Gaussian centers, k exact whole-vector values, and a separately generated independent Gaussian output-noise vector. The query cap is deterministic, and no derivative or hidden encoder is assumed. The conservative structure is unused; the same bound holds for every globally Lipschitz vector map.

This establishes an upper bound on the law of a sampler output. The oracle still returns each exact g(G_j) value before the caller adds noise. Data processing only says that the deliberately noised output has no more information than that exact response; it gives no upper bound on information in the raw response. The comparison target is N(m,sigma^2 I) with the same unknown mean m. For fields with means m_0 and m_1, their target Gaussians have:

\[
\operatorname{TV}(N(m_0,\sigma^2I),N(m_1,\sigma^2I))
=2\Phi\!\left(\frac{\|m_0-m_1\|_2}{2\sigma}\right)-1.
\]

Thus a constant-size mean difference remains a constant target separation; the lemma does not put both outputs near a common reference distribution. A lower bound or information-hiding argument must separately compare raw oracle transcripts or establish that competing target means are close.

The query and arithmetic statement is in the ideal-real model. If outputs are compared after a common finite-bit quantizer Q, data processing gives TV(Q(Y),Q(N(m,sigma^2 I)))<=epsilon. That does not certify finite-bit Gaussian input generation, output-noise generation, evaluation or rounding of exact oracle values, or end-to-end arithmetic error. A finite-support digital output compared to the unrounded continuous Gaussian instead has TV 1. These are separate implementation costs, not flaws in the ideal-real inequality.
