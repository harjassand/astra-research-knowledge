# Frozen first derivation: generator-image learning with a self-test

Status: frozen before literature comparison (2026-10-10). This is a candidate mechanism, not a novelty claim.

## Interface and representation

Let G be a known finite group generated by a listed set S of size d, with an algorithm and stated cost for expressing a queried group element as a word over S. Let H be a known finite group with exact encodings and multiplication. The target is an unknown total map f:G→H. The learner has only chosen membership queries g↦f(g); there is no equivalence oracle, counterexample teacher, or access to target code. A reply costs log2|H| bits; each query input costs its word length in S-symbols (or the cost of the supplied word representation). The promise is that f is a homomorphism. A separate mode drops the promise and asks for a property-test, not exact certification.

Represent a target by the tuple (f(s))_{s∈S}, rather than by a syntax tree or a table over G. For a word w=s_1^{e_1}…s_m^{e_m}, evaluate the hypothesis as the corresponding product of generator images. Relations in G guarantee this is well-defined exactly when the tuple satisfies the relators of G.

## Exact theorem under the promise

Query f(s) once for every s∈S. The resulting tuple determines f on every element of G by multiplicative extension. Proof: if g is represented by a word w in S, the homomorphism law gives f(g)=f(s_1)^{e_1}…f(s_m)^{e_m}; this value is independent of word choice because f is already a well-defined homomorphism. Thus d target calls suffice, plus local group operations proportional to the representation length of each later evaluation.

For the class Hom(G,H), every query returns at most log2|H| bits. A transcript of q queries has at most |H|^q possible reply strings, so exact identification requires q≥ceil(log_|H| |Hom(G,H)|) in the worst case. The d-query procedure is optimal when |Hom(G,H)|=|H|^d (e.g. the free group on d generators), and remains within a factor bounded by the relations' information in other presentations. For G=(Z_2)^d and H=Z_2, the class is all binary linear functionals: d basis queries are necessary and sufficient, versus 2^d queries to tabulate the domain.

## Boundary: syntax/composition by itself buys nothing

For X of size N, the one-module class {h:X→{0,1}} has 2^N members and is a compositional class (e.g. id∘h). With q membership queries, at least 2^(N−q) candidates remain consistent in the worst case. Under a uniform random target from this class and a uniform independent test point, any learner's expected risk is at least (N−q)/(2N), since every unqueried target bit is still uniform. Therefore short programs or reuse in syntax do not imply learnability; the effective algebraic restriction must be real and observable.

## Positive extension candidate: self-testing rather than trusting the promise

A learner could query generator images to produce the only possible homomorphic candidate, then use random triples (a,b,ab) and check f(ab)=f(a)f(b). Each check uses three ordinary membership calls and no teacher. If the relevant group-homomorphism tester has soundness Ω(ε) for ε-far functions under the declared sampling distribution, O(ε^−1 log(1/δ)) checks reject with probability 1−δ; exact acceptance cannot certify zero distance with finitely many queries. A concrete implementation must state group sampling, encodings, and representation costs. This step is a candidate until primary-source audit verifies the soundness and scope.

## Why this may fail as a landmark

The promised-case algorithm is the elementary presentation of a known algebraic map by generator images. The closest baseline likely has the same query count. The only potential gain is an explicit reusable semantic representation plus a no-equivalence-oracle audit. If prior art covers this uniformly, or the tester requires hidden distributional assumptions/extra access, this candidate is rejected. No mission-completion claim follows from the theorem.
