# W13 provenance and supersession audit

Scope: read-only audit of Astra index/card metadata, current Y and Z intakes, and selected correction/import cases. No scientific scripts were run and no broad runtime binaries were inspected. Findings describe packaging/provenance only, not mathematical validity.

## Findings

1. **The base build inventory is current by count, while its timestamp is the original build time.** `indexes/BUILD.json` says `built_at_utc=2026-10-07T04:06:24Z`, but its `updated_at_utc=2026-10-07T16:07:06Z` matches Z intake. Its totals match the present indexes: 30,743 file rows, 11,376 source-metadata rows, and 186 claims. This is not a demonstrated count error, but `built_at_utc` alone looks stale and does not identify which fields were refreshed. Add a separate `index_snapshot_at`/per-index generation time or make the meaning of `built_at_utc` explicit.

2. **The full `VALIDATION.json` is stale after Y and Z.** It was checked at `2026-10-07T12:39:48Z`, before Y (`14:22:42Z`) and Z (`16:07:06Z`). Its card-source validation covers 169 cards, while `claims.jsonl` now has 186. Its archive CRC fixture lists only `ASTRA_CARD_PACK.zip` and `ASTRA_WEB_TEXT.zip`, not the later Y/Z snapshots. Treat this pass as validation of the earlier snapshot only; it must not be presented as validation of current indexes or the Y/Z archives. `LATEST_UPDATE_VALIDATION.json` is an older retrieval fixture (N01–N05) and likewise is not a latest-Y/Z check despite its filename.

3. **Y/Z source metadata intentionally omits the derived outer archives, but counts use different meanings.** Y has 22 file-index rows and 21 source-metadata rows; the omitted path is `updates/Y/quartic_fermion_Y_snapshot.zip`. Z has 23 file rows and 22 metadata rows; omitted path is `updates/Z/astra_20261008_research_Z_snapshot.zip`. Both are described as derived lossless archives, and their archive hashes are recorded in the respective update-validation JSON. This appears coherent if metadata rows mean payload files, but `Y_UPDATE_VALIDATION.sources=22` and `Z_UPDATE_VALIDATION.sources=23` equal indexed rows including the archive; clarify whether `sources` counts payloads, all indexed objects, or source documents. Current BUILD metadata total includes all indexed entries; do not compare it directly with payload-only source metadata counts.

4. **Selected claim-to-source mapping is path-consistent.** All source paths for N100/N105/N108 (Y), N109/N110/N115/N116 (Z), and N94 (W) resolve in `files.jsonl`; the corresponding file rows have SHA-256 values and the same paths appear in source metadata, with expected Y/Z archive exclusions above. No dangling selected claim source path was found. Z N116 names 16 evidence source IDs; Z package metadata has 22 payload entries, so this is a curated evidence subset rather than a complete package manifest. That is acceptable, but consumers should not infer that every indexed payload is cited by every card.

5. **Some Z check outputs are byte-identical under distinct paths.** `checks/results.json` and `checks/replay_base.log` share SHA-256 `1c091838…`; `checks/stability_results.json` and `checks/replay_stability.log` share `8949a2d6…`. This may be intentional copied output, not corruption. Preserve the distinct paths and roles, but consider recording an `identical_to` relation so duplicate immutable objects are visibly aliases rather than independent corroboration. The `files.jsonl` mapping itself preserves both paths and hashes.

6. **Status language on current Y/Z cards is appropriately scoped, with one useful caution.** N105 explicitly marks Tang et al. Theorem 2 at `g=0` as an imported premise whose full proof was not independently certified; it scopes its derived lower bound to the stated input-loss/Gaussian-processing architecture. N109/N110 retain Chen–Liu and BGLW dependencies, and N115 states corrected limits without upgrading the sampler/hardness conclusion. N116 explicitly says diagnostics were reported by the source and not rerun during ingestion. This matches Y/Z validation fields (`source_diagnostics_replayed=false`, `scientific_validation=false`, no formal/external verification). Keep “complete supplied evidence package” distinct from complete proof review or scientific validation; the cards currently do so in their leading status lines.

7. **Corrections and withdrawals are mostly embedded in prose, not represented as queryable lineage edges.** Examples: N47 says the initial FJ contradiction was withdrawn; N65/N70 repeat that correction, and N115 records corrected prior route claims. N53 encodes a scoped supersession of N39 through `scoped_dependencies`, but ordinary corrections/withdrawals elsewhere are prose-only. A search can retrieve the caveat, but an index consumer cannot reliably determine which earlier claim is withdrawn, which scope survives, or what replacement governs.

## Recommended freshness and supersession rules

- Give each generated index/validation artifact a `snapshot_id` (or input-manifest hash), generation timestamp, and covered source/update IDs. A `pass` applies only to that exact snapshot. On any later update, label it `stale_for_current_snapshot` until rerun; never let an earlier pass inherit forward silently.
- Separate counters explicitly: `indexed_paths` (including archives), `payload_objects`, `metadata_records`, `unique_content_objects`, `claims`, and `validated_claims`. Include the inclusion rule for each counter. For Y/Z, record the outer archive as a derived container with its own archive hash and no payload-level source metadata row.
- Treat content-addressed objects as immutable. A changed byte sequence creates a new object/hash; do not overwrite. Repeated identical bytes at different paths should map to one object plus multiple path/role aliases. Record source path, origin path, intake/update ID, manifest membership/hash, and transformation/archive lineage separately.
- Add machine-readable claim relations with typed scope: `corrects`, `withdraws`, `supersedes`, `narrows`, `imports`, and `depends_on`. Each relation should identify the target claim/version and the exact proposition or interface it affects. A correction should never erase historical text; it marks the affected version withdrawn and points to the current scoped replacement. Unaffected subclaims remain active.
- Keep status dimensions orthogonal rather than promoting a card wholesale: source-reported diagnostics, ingestion/hash integrity, internal reconstruction, finite replay, formal proof, independent review, and priority/prior-art should each carry provenance and scope. An imported premise remains imported even when a downstream conditional derivation is internally checked.
- Add a freshness audit asserting: every claim source path exists; every source ID resolves to one path/hash; each update's payload/archive counts reconcile; card evidence IDs belong to the stated update or are explicitly imported; and each validation timestamp covers the exact current snapshot. Report mismatches without changing claim status.

## Evidence boundary

This was a bounded lineage audit, not a scientific proof audit, source-by-source archive replay, novelty review, or complete audit of all withdrawn/imported results. The observed base `VALIDATION.json` staleness is definite from its timestamp and 169-card count; the proposed meaning of its current replacement is a metadata design recommendation.
