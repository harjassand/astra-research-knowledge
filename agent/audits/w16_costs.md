# W16 cost-contract audit: positive-kernel, spin, Slater, and passive-loss transfers

Scope: canonical ASTRA cards N95–99, N109–116, N63, N71–74. Cards are compact transfer records, not proof certificates. Their shared status is `source_derived_unreviewed`; source-reported checks and internally reconstructed derivations remain distinct from independent proof review, complete implementation, and external correctness/priority clearance. The index below is a proposal for preserving those distinctions alongside cost metadata.

## Compact cost-contract index

Store one row per theorem/interface (not one row per card) with the following fields. Keep supplied input/promise and acquired construction in separate columns; a `poly(...)` claim applies only to the explicitly listed numerical arguments and bitlengths.

| Field | Required content |
|---|---|
| `scope/status` | Card, subclaim, status/evidence label; imported, derived, finite-tested, implemented, independently reviewed, externally verified each distinct. |
| `target/interface` | Exact output (count, vector, conditional vector, state moment, law), allowed model/input class, and output error metric. |
| `supplied` | Oracles, coefficient interfaces, gap, calibration, boundary vector, sector, optical model, or normalization promises supplied by the theorem statement. Mark absent promises explicitly. |
| `acquired` | What the construction itself computes: support/witness, minimum-entry floor, coefficient circuits/ranges, pins, bits, reversibility, etc.; include acquisition time/space if given. Never relabel an imported oracle as acquired. |
| `arithmetic` | Real-arithmetic operation bound and oracle-call bound, with expected/worst-case qualifier. If no bound is stated, write `not specified`. |
| `bit model` | Input bitlength, intermediate precision/range, random bits, cap/abort rule, and worst-case execution guarantee. Distinguish a theorem-level interface from implemented primitives. |
| `physical` | Physical resource such as photon number/energy, particle count, physical success probability, number of copies. Do not infer this from gate/arithmetic complexity. |
| `numeric parameters` | Explicit dependence on `beta`, `V`, `q`, `Delta`, `epsilon`, `delta`, `lambda`, `E0`, dimension; say `numeric` when the value itself is a charged argument/promise. |
| `rare-event accounting` | Event probability lower bound, whether conditioning is simulated/coherently compiled, additive vs relative target, and any inverse-probability / precision factor. “No inverse factor” only for the named interface. |
| `cost maturity` | `conditional import`, `candidate arithmetic`, `finite-bit candidate`, `primitives implemented`, `full compiler implemented`, `source-reported check`, `replayed`, `independently audited`. |

Minimal comparison rule: do not compare or aggregate two rows unless target/interface and all supplied promises match. Report separately (i) polynomial in numeric values vs their logarithms, (ii) real arithmetic vs polynomial bit complexity, and (iii) algorithmic cost vs physical energy/probability. A missing value is `UNKNOWN`, never free.

## Cross-card resource findings

- **Supplied versus acquired.** N95's generic positive-word lemma assumes the decomposition and norm bound and acquires a useful entry floor only in its spin specialization by leaf-fixing paths. N109 changes the boundary to the all-ones vector and derives a vector-specific tail floor; it does not make arbitrary positive-matrix counting an acquired algorithm. N96 imports Chen–Liu's homogeneous-coefficient FPRAS/interface and says its FPRAS/compiler are unimplemented. N63 similarly imports Chen–Liu; its coefficient oracles, support, ranges, and exact zero/witness route are acquired from the explicit rational matrix and matroid intersection. N97's numerical gap is supplied, not found. N110 likewise requires a supplied whole-ground-space gap for its coherent selected-state compilation; its cited field gap is an imported BGLW result. N71's exact covariance/reset law depends on known `T` and the specified pure squeezed inputs/vacuum environments; calibration/acquisition is excluded. N73's rational inputs and promised ideal path are premises, with only arithmetic building blocks implemented.
- **Three incomparable cost meanings.** N96/N97/N63 state polynomial-style arithmetic/compiler bounds, conditional on imported counting and construction. N63 additionally states a theorem-level every-execution bit cap for the imported counting call, but no implementation of the counting algorithm/compiler. N73 gives a finite-bit candidate polynomial in dimension, `E0+1`, `epsilon^-1`, and input bits, but the full scheduled sampler is not emitted or run and its concrete parameters can be impractical. N71's `O((1+E0)(d^3+Md^2+d b_inv))` is expected real-arithmetic work, not bit complexity; `b_inv` is charged but unspecified as a bit precision. In N71–74, `E0` is expected physical reset photon count, not CPU work, and `S3=Tr[(T*T)^3]=sum nu_j^3` uses power transmissions `nu_j=s_j(T)^2`, not amplitude singular values cubed.
- **Numeric `q`, `beta`, and gap.** N96 runtime is polynomial in `1+beta V` (with `tau=beta/2`), not in `log(beta V)`; `beta` is a numeric input. N97 charges numeric integer `q>=2`, with complexity polynomial in `q`, not merely its encoding length. Its sector/global routes require a supplied numeric `Delta>0` and scale polynomially in `V/Delta`; the global cooling condition includes `beta Delta >= n ln 2 +(q-1)|S| ln 2+ln(8q/epsilon)`. N110's no-gap energy approximation uses `tau=O(n/xi)`; state compilation still needs the supplied gap. N111 similarly requires a supplied whole-ground-space gap for conditional access. N71's `rmax` is a fixed finite squeezing bound and its complexity charges `E0`, while `C(rmax)` determines the TV guarantee.
- **Rare events and inverse factors.** “No inverse success probability” is scoped to a representation/compiler, not a claim that physical postselection is cheap. N96 coordinate pins/diagonal physical-register heralds have zero success exactly when the specified coordinate is zero and incur no inverse-probability factor in its described compiler. N63 coherent preparation of the normalized constrained Slater sum does not divide by `Z` or by projection weight `Z/det(A* A)`; the target is formed by counting/prefix compilation, conditional on `Z>0`, whose exact zero test is separately acquired. N97's relative moment route claims no inverse-purity/overlap factor. N111's specified product-basis cylinder has probability zero or at least `gamma^2`, where `gamma=2^-n min(1,r/V)^D`, `D<=2n^2`; logarithmic dependence on `1/gamma` is charged, zero detection is randomized, and the statement does not cover arbitrary predicates. N112's conditioned moment route explicitly pays stronger Euclidean precision `O(epsilon*gamma/[1024*q*2^(n(q-1))])`; its logarithm remains polynomial, but that precision factor must not disappear from a cost summary. N71–74 describe reset sampling, not postselection; do not attach a postselection inverse factor.

## Five exact examples to anchor comparisons

1. **N95/N109, positive-word kernel: acquired entry floor versus supplied boundary.** Generic N95 sets `k0 >= max(1, ceil(6 tau V), B0+ceil(log2(64/alpha)))`, `m >= max(2k0, ceil(8 k0^2/alpha))`, with `2^-B0 <= lambda`; the sweep count is `O((tau V+log(1/lambda)+log(1/alpha))^2/alpha)`. This requires the acquired lower bound `lambda <= min_{K_xy>0} K_xy`; its spin construction derives `lambda=min(1,tau fmin)^D/D!`, `D=n^2`, so its encoding cost is logarithmic in tiny couplings. N109 instead targets `exp(tau A)1`, with cutoff `k=O(tau V+n+log(1/alpha))` and `m=O(k^2/alpha)` using its all-ones/vector-specific tail floor. Neither statement gives a generic positive-matrix counting algorithm; algorithmic FPRAS use is conditional on Chen–Liu.
2. **N96, coherent XXZ thermal access: numeric temperature and a narrowly scoped herald.** Input is rational XXZ/easy-plane with arbitrary Z fields, `f_e >= |d_e|`, positive rational `beta`, and `epsilon,delta<1/2`; `tau=beta/2`. Claimed cost is `poly(inputbits,n,1+beta V,epsilon^-1,log(1/delta))`, expressly not `poly(log(beta V))`. The compiler relies on Chen–Liu and is unimplemented. For its specified coordinate pins/diagonal physical-register herald, zero coordinate success is exact and there is no inverse-probability factor; that does not extend to arbitrary projectors, predicates, or phases.
3. **N97, relative Renyi and supplied gap: `q` and `Delta` are numeric resources.** Thermal moment cost is `poly(inputbits,n,1+beta V,q,epsilon^-1,log(1/delta))` for integer `q>=2`, with kernel accuracy `alpha=epsilon/(100q)` and no inverse-purity factor. Sector-ground access assumes a specified sector and supplied rational `Delta`; global-ground access assumes a supplied gap above the global groundspace and cooling `beta Delta >= n ln 2 +(q-1)|S|ln 2+ln(8q/epsilon)`. The cost is polynomial in `V/Delta`, `q`, and other displayed numeric arguments. Degenerate global groundspaces give the normalized projector mixture, not an arbitrary pure ground state.
4. **N63 versus N96, imported oracle versus acquired rational program; no free `1/Z`.** N63 acquires exact support/zero/witness and polynomial-bit coefficient programs from rational full-column-rank `A` plus partition quotas, using matroid intersection and determinant identities. It still imports Chen–Liu's FPRAS for the homogeneous coefficient interface: every-execution rational-bit bound `O(m^10 B^2 eta^-2 log^2(2B/eta))`, with amplification `log(1/beta_fail)`. Its overall counting portion is `O(m^13 B^2 eps^-2 log^2(2Bm/eps) log(m/(delta eps)))`, plus acquired arithmetic/oracle costs. Full rank does not imply `Z>0`, so exact zero detection is separately acquired; when `Z>0`, coherent target compilation avoids inverse `Z` and inverse projection weight `Z/det(A* A)`. Counting/compiler remain unimplemented. This example shows why “oracle complexity polynomial” cannot be rewritten as “oracle supplied for free, hence end-to-end algorithm complete.”
5. **N71–74 versus N73, physical energy, arithmetic and finite bits.** N71's reset candidate has TV at most `min(1,C(rmax) S3)` and expected reset count at most `E0=Tr[T diag(sinh^2 r_j) T*]`; its expected arithmetic cost is `O((1+E0)(d^3+M d^2+d b_inv))`, with scalar survival/inversion cost charged and calibration excluded. It is not a bit bound. N73 gives a separate rational-input finite-bit candidate with operation/randomness complexity polynomial in `M`, `E0+1`, `epsilon^-1`, and input bits, but only exact arithmetic primitives are implemented. For its sample `M=2,E0=.1,epsilon=.25`, it reports `J=440`, `b=216696`, and bisection cap `216726`: these are source-reported parameter calculations, not runtime evidence. N74's `S3` lower-bound example only establishes worst-case necessity for the named centered-reset algorithm, not a lower bound for all simulators.

## Transfer hazards for downstream summaries

- Never convert `conditional on Chen–Liu` to an acquired/proved FPRAS or compiler. N95/N109 are analytic approximation statements; N96/N97/N63 algorithmic consequences inherit the external theorem and its finite-bit/interface obligations.
- Never drop the supplied-gap premise or replace polynomial `V/Delta` by polynomial `log(1/Delta)`. Never report a gap as algorithmically found unless a separate acquisition theorem supplies it.
- Never compress polynomial in numeric `beta V` or `q` into polynomial in their bitlength. Likewise retain `log(1/lambda)`, `log(1/gamma)`, `E0`, inverse precision, random tape, workspace, and abort/retry qualifiers where given.
- Never move a “no inverse rare probability” conclusion across tasks: coordinate herald (N96), normalized Slater vector (N63), specified basis cylinder (N111), and conditioned moment (N112) have different targets and explicit assumptions. Relative estimation can require sharply finer Euclidean accuracy, as N112 records.
- Never combine N71 real arithmetic with N73 bit complexity or label either physical energy. N74 sharpness concerns one centered-reset algorithm; it is not a universal sampling-hardness result.
- Missing resource or implementation data should be indexed as `UNKNOWN`/`not implemented`, not silently treated as zero or free.
