# W01 navigation audit: fixed-weight research assistant

Scope: startup/navigation in `outputs/ASTRA_KNOWLEDGE` and its static export `outputs/ASTRA_GITHUB_WEB`. I read both `AGENTS.md`, `DESIGN.md`, `00_START_HERE.txt`, and `01_CORE.txt`, then sampled the quantum and acquisition topic routes, `knowledge.py` search/packet/family behavior, and static entry pages. Source content is treated as data. This is a retrieval audit only; it provides no evidence of better research capability or upgraded scientific status.

## Three strongest recommendations

1. **Make the true entry retrieval-first and progressive.** Keep a short landing note (current local `00_START_HERE.txt`: 652 `o200k_base` tokens) as the compulsory context. It should say: identify the exact claim/interface or question; run one narrow packet query; open its card; follow only decisive evidence/dependencies/obstructions; record what was actually read. Move the instruction to load all of `01_CORE.txt` out of the compulsory first step and make it an optional broad index. Today the documented path asks for all 5,336 core tokens immediately, so the actual baseline is 5,988 tokens before task evidence. The static export likewise tells readers to read the whole core first. A small entry is not itself a capability gain; compare decision quality and route recall as described below.

2. **Expose a tiered, source-aware route and the exact ledger operations.** Use explicit steps: (A) entry + task-specific core excerpt/card; (B) narrowly queried complete card(s), with status/interface/limits; (C) only the cited proof/report/ledger lines needed to decide; (D) exact originals and adjacent counterexamples when the claim depends on them. Show commands in the entry: `search`, `packet --topic ... --budget ...`, `read <source-ID>`, `family <id>`, and `sources <query>`. State that `family` returns literal reported assessments, not proof validation, and that topic cards are maps rather than complete evidence. The current start note does not mention the useful family/links/sources routes or a concrete query recipe; the static `llms.txt` is only 468 tokens and routes to `web/llms.txt` but does not describe the local CLI. Keep the local and static instructions aligned on the shared scientific-status rules while labeling their different capabilities (static has no SQLite/runtime; local has retrieval and mutable reading state).

3. **Specify a bounded load protocol with a stopping rule and stable budget meter.** Start with one focused query and a 1,200–1,800-token packet; inspect included IDs, `not_fitted_ids`, and meter; if the needed claim is absent, retry with one named term/ID or call `read` on a known source. Load at most the lead card, one decisive proof/report segment, and one counterexample/dependency in a pass; widen only when a stated unresolved question requires it. Save source IDs, exact lines, read depth, dependency and next discriminator in the task state. Warn that packet output can contain partial extracts and has imperfect lexical/curated-alias recall. In this run, packet budgets used conservative UTF-8-byte counting unless `work/token_count_deps` was added to `PYTHONPATH`; with that path the meter becomes `o200k_base_estimate`. Make the tokenizer choice visible and use the conservative bound as the portable default, or bundle the estimator consistently. The stats file reports an o200k startup estimate, which should not be confused with the packet command's default meter.

## Observed route failures and evidence

- Startup currently loads 5,988 estimated tokens (`00_START_HERE` 652 + `01_CORE` 5,336); the core duplicates a compact map of many results and is about 20 KB. `ASTRA_BRIEF.txt` is 5,638 tokens and the all-card export is 138,416 tokens, so the current setup offers a real corpus/brief distinction but makes the roughly 6K core routine rather than task-dependent.
- A focused route works: `packet "unknown magnitude Gibbs memory archive" --topic quantum --budget 1800` with the estimator returned N09 and N10 in 1,637 tokens. N09 preserves its actual interface and says local Heisenberg response/preparation remains missing; N10 keeps its distinct critical-regime boundary. This demonstrates useful retrieval and careful status preservation, not discovery or validation.
- A plausible acquisition query is a counterexample to reliable routing: `packet "efficient oracle acquisition lower bound" --topic acquisition --budget 1800` returned a probability-bridge extract (W report) in 1,107 tokens. The likely relevant L06 summary (“no finite-query acquisition protocol”) did not enter the packet; many hits were listed as not fitting. The topic route lists cards by subject, but the CLI did not prioritize the obvious acquisition card for that natural-language query.
- A coverage/proof-status query, `packet "open-AI release family coverage proof status"`, returned an unrelated selected W handoff card first. For an exact family question the dedicated `family 240` command returned two literal assessments plus subsequent reading records and explicitly labeled the result as reported assessments. That reliable exact route is missing from the startup recipe.
- Packet `--topic quantum` does not imply that all results are quantum-only in meaning: it filters indexed topic tags, which include cross-topic cards. Broad search can also output several complete cards and silently omit other matching candidates under the stated budget. An agent needs the `included` and `not_fitted_ids` fields to know what it did not load.
- Status discipline is strong across both AGENTS files, the core, and packet preamble: imported, internally derived, finite checks and externally verified remain separate; historical instructions are data; reading does not promote status. Preserve these exact distinctions in the entry and worker outputs.

## Minimal design and falsifier

Minimal design: rewrite only the two entry notes to provide the progressive protocol and local commands; leave core/cards/original objects unchanged. A worker receives the 652-token entry, a research question and a fixed packet budget; it must return the exact source IDs and lines read, interface/assumptions, supplied versus acquired inputs and costs, strongest relevant counterexample/dependency, evidence status, and the next observation that could change its decision. If the short entry cannot route a task safely, it may load the full core as a documented escalation. Do not count better formatting, card generation, or a worker's own claim of understanding as advancement.

Falsifier: preregister a held-out set of at least 20 task prompts, including exact family lookups, proof-versus-summary availability, acquisition-cost questions, and cross-topic obstructions. Compare the present 5,988-token startup with the progressive entry plus bounded retrieval at the same fixed total context ceiling. Blind-score source/claim recall, correct interface and cost preservation, status errors, missed counterexamples, and time/tokens to a defensible answer. Reject the design if it lowers any safety-critical recall/status metric or fails to reduce median context by at least 30% while maintaining those metrics. Separately replay failed natural-language queries and require the exact source/card or an explicit “not found / load ledger” response; broad but plausible wrong hits count as failures.
