# W15 — ingestion, refresh, and publication architecture

## Finding

The system already has the right data concepts in its canonical `outputs/ASTRA_KNOWLEDGE/UPDATE_PROTOCOL.txt`: immutable SHA-256 originals, source metadata/read depth, stable claim IDs, scoped dependencies, retained derivations, and synchronized routers/search/static output. The implementation does not enforce that protocol through one pipeline. It has many letter-specific scripts that mutate the same SQLite database, JSONL mirrors, cards, topic files, and static pages directly; `refresh_astra_exports.py` and `sync_astra_github_M.py` then apply a second layer of generated output. Z's post-ingest reference repair is direct evidence of schema/path drift.

This is an architecture audit and proposed design, not a proof or source-content review. Z metadata records manifest/archive integrity and explicitly says diagnostics were not replayed and scientific validation is false.

## Highest-risk failure modes

1. **Partial updates can leave the knowledge base internally inconsistent.** In `work/add_astra_Z_results.py`, lines 154–155 commit SQLite before appending file/document/chunk/card mirrors; later writes update aliases, metadata, queues, topics, core, brief, transfer map, and build metadata (156–181). Any exception after the commit leaves DB and filesystem mirrors at different generations. Direct writes are not staged or atomically replaced. The refresh script similarly writes many outputs in sequence (`work/refresh_astra_exports.py:10–18, 36–81`), so interruption can publish a mixed generation.

2. **The schema and source path contract are implicit and have already drifted.** Z's ingester maps files under keys like `package/<path>` and emits source IDs/paths in several representations (`work/add_astra_Z_results.py:96–140, 141–153`). The separate `work/repair_astra_Z_card_refs.py` had to correct references in eight curated cards, update SQLite document/chunk/card records, rebuild FTS, and rewrite JSONL mirrors. That repair is a hand-authored second implementation of card serialization and indexing. Future source-path fixes can update only one representation. Stable IDs also use a truncated hash of a path (`add_astra_Z_results.py:52`), while content identity is separately the SHA-256; neither identity contract is declared in a common schema.

3. **The scripts are near-duplicate forks with letter-specific assumptions.** The Z ingester hardcodes a download directory, intake folder, tag, classifications, topic routing, report paths, and prose (`add_astra_Z_results.py:7–12, 47–58, 112–128, 149–181`). The Y/W etc. scripts repeat the machinery with small variations. A fix to path normalization, extraction, chunking, token accounting, or transaction ordering therefore has no guarantee of reaching every letter. `sync_astra_github_M.py` is also the W–Z mirror builder despite its name and contains a growing series of string substitutions and per-letter append blocks (`sync_astra_github_M.py:1–55+`).

4. **Exact originals and searchable text are different objects, but the distinction is not enforced by a common type.** Z correctly puts exact bytes in the content-addressed object store and separately records extracted text (`add_astra_Z_results.py:77–94, 112–124`). HTML extraction is explicitly lossy and binary inputs are metadata-only. However the shared data layer should encode original-byte hash/size/object reference separately from extracted-text hash, extraction method/status, and searchable payload. Today those values are assembled ad hoc, increasing the chance that a derived or normalized text is mistaken for the immutable original. Manifest verification exists in the Z intake artifact (`work/Z_INTAKE_VALIDATION.json`) but is not visibly a mandatory generic precondition in every ingester.

5. **Token fields can silently stop agreeing with the rendered card.** Z computes `o200k_base` through `tok()` and writes card tokens from its generated full card text (`add_astra_Z_results.py:12–13, 140–143`); `refresh_astra_exports.py` later regenerates exports from DB/claims and recomputes only selected aggregate token counts (`refresh_astra_exports.py:13, 15–18, 77`). Z's special reference repair separately updates DB card tokens and JSONL token fields. The canonical invariant should be `cards.tokens == o200k_base(exact UTF-8 text at cards.path)`, with source/document and chunk token counts similarly tied to their actual text fields. Token unit and tokenizer version should be explicit in build metadata; aggregate token counts must be recomputed from the staged generation.

6. **Public mirrors are assembled from a partial, manually curated file list.** `work/sync_astra_github_M.py:10–20` copies selected indexes and outputs, rather than deriving the mirror from a declared publication manifest. Its later link checks cover selected generated pages/lists but don't assert that every local public alias points to the intended card/source, that the copied artifacts all share one build ID, or that no stale alias remains. The W–Z updates are maintained through chained text substitutions and one-off appended prose (`sync_astra_github_M.py:21–55+`). A passing link check can therefore coexist with semantically stale start-here text or index data.

7. **Idempotency is partial.** Z rejects a second run if its first card already exists (`add_astra_Z_results.py:28`), but that means a crash after any mutation blocks a clean retry. Several outputs append unconditionally (topic routers, queue, core/brief, README, llms, update history). Some whole-index files are rewritten from DB, others appended from lists. The expected behavior for same source hash, changed source bytes, corrected curation, and retry after partial failure is not centralized.

## Minimal maintainable design

Keep the existing tables and output formats initially. Add one small generic intake/build module and make each `add_astra_*` file a declarative input wrapper (source location, package manifest, card specs, source-role/topic overrides, update summary). Do not begin with a broad rewrite of retrieval or graph semantics.

1. **One normalized input schema.** Validate an update object with `update_id`, `source_snapshot` (origin, manifest hash, archive metadata), `files[]` (relative path, original SHA-256, byte size, role, extraction policy, provenance), and `claims[]` (stable ID, title, exact status, body, topics, source paths, typed scoped dependencies, aliases). Resolve every path once to a canonical package-relative POSIX path. Reject missing, duplicate, traversal, unlisted, and hash-mismatched members before writing to the knowledge store. Keep external dependency IDs distinct from claim IDs and source-document IDs.

2. **Immutable evidence ingestion first.** Copy exact bytes into the SHA-addressed object store with temp-file plus atomic rename; verify digest after write. Record origin path/metadata without using machine-specific absolute paths as lookup keys. A derived lossless ZIP is a separate artifact with its own hash and provenance, never a replacement for member originals. Preserve exact raw bytes even when extraction is unsupported or lossy.

3. **Pure staging/build phase.** From the validated input plus the current base generation, derive docs, extracted text, chunks, FTS rows, cards, edges, aliases, reading queue, topic shards, startup/brief exports, static pages, public aliases, and build statistics in a staging directory/database. Each derived record should point back to stable original IDs/hashes. Define token counts from exact serialized text using one named encoding/version. No direct append operations: merge keyed records deterministically so retrying the same update yields byte-identical outputs.

4. **Cross-artifact validation before activation.** Validate schema and IDs; all claim source paths resolve; all dependency endpoints exist in the typed node registry; original objects match hashes; card/document/chunk token counts recompute; database FTS and integrity checks pass; JSONL mirrors round-trip and match canonical DB rows; aliases resolve to existing claims; every generated relative public link resolves; public manifest hashes every published file; build counts derive from the staged artifacts. Include representative alias and direct-search fixtures, including the known short-alias/stopword normalization issue in `work/astra_system_audit/w02_retrieval.md`.

5. **One activation point.** Use a SQLite transaction for the canonical DB and a generation directory/symlink or manifest pointer for filesystem outputs. Build all artifacts under `builds/<generation-id>/`, validate, then atomically switch the active generation pointer. Keep the prior generation recoverable. A failure before activation changes no active index or public alias. For the initial small implementation, a lock plus backup/restore can work, but document the crash guarantees.

6. **Refresh and public sync become deterministic consumers.** `refresh_astra_exports.py` should become `build_exports(generation)` and produce outputs only from normalized canonical records. `sync_astra_github_M.py` should become a publisher that copies only files listed in a generated publication manifest, verifies copied hashes/links/aliases, and emits the published generation ID. Neither script should add claim text or infer prior updates by searching/changing old prose. Keep the protocol text as a human-readable contract and add schema/version pointers to it.

## Testable acceptance checks

- **Bad manifest:** one altered payload hash, one missing member, duplicate relative path, and `../` path each fail before any active DB/index/public files change.
- **Exact-byte identity:** ingest a file, ingest an exact duplicate at another origin, and ingest one changed byte. The duplicate reuses the same object hash but retains provenance; the changed object gets a new hash; original objects are never overwritten.
- **Idempotent retry:** build the same update twice from the same base and compare generation manifests and derived artifacts byte-for-byte; counts do not grow twice and append-only router/queue text does not duplicate.
- **Schema/path regression:** every curated card's `source_paths` and rendered `EVIDENCE` links resolve to its actual source document; no special Z repair script is required. Verify the eight Z cards that previously needed correction.
- **Token consistency:** recompute each card token count from the exact card file; recompute document/chunk counts from stored text with the declared tokenizer; assert SQLite, JSONL, exports, and public catalogue agree on the same card token values.
- **Transactional failure injection:** force a failure after object ingestion, during SQLite insert, after DB validation, and during mirror generation. The active generation remains wholly old or wholly new, never mixed, and retry succeeds.
- **Alias/public routing:** every alias ID resolves to a card; aliases normalize through the same tokenizer/stopword path as lexical retrieval; each published alias/page URL resolves to that same card. A syntactically valid but stale link should fail semantic route validation.
- **Rebuild parity:** rebuild search/export/public artifacts from canonical records alone and compare with committed generation manifests; check public root, card catalog, representative source pages, and `llms.txt` all advertise the same generation.

## Suggested implementation order

Start with schema validation and path normalization before any mutation; this directly prevents another Z-style repair. Next add a staging build with deterministic keyed merges and token/hash cross-checks. Then add activation/rollback and convert the letter scripts into data wrappers. Finally replace the M-named mirror script's per-letter prose substitutions with manifest-driven publication. This keeps exact originals and current curated claims while making every derived index and public alias reproducible from one validated input.
