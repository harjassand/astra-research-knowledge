# Implemented public-agent architecture audit

Audited input: main `8aed7fd74eb14622ed5a0a3635a799374296e32a`, retrieved 10 October 2026. At that revision the public records contain 604 scoped cards, 91 curated proof gates and 243 extracted lemma records. These counts describe that inventory, not validated discoveries. Current generated counts are in `agent/CURRENT.txt`.

The audit began at `00_START_HERE.txt`, read the agent protocols and public retrieval/build code, inspected record schemas and source examples, and used separate read-only composition/notation and continuity inspections. It introduced no scientific investigation or model evaluation. Official product guidance and capability boundaries are recorded in `agent/OPENAI_GUIDANCE.md`.

## Findings and implemented choices

| Observed limitation | Implemented change |
|---|---|
| Topic routing works, but analysis/methods each contain hundreds of cards; alias metadata is only globally available | Small alphabetic lexical shards over existing aliases plus titles; every card participates, including new intakes lacking an alias |
| 9.5 MB typed graph and 3.7 MB status ledger are impractical mandatory web reads | Direct per-result dossiers and exact incident graph projections; old sidecars/topics remain compatible |
| Proof ranges point into whole HTML sources; some pages put correction banners in earlier pre blocks | SHA-selected source recovery and bounded unchanged proof-range payloads, with inclusive original line locators |
| Public checkout lacks private SQLite/full-snapshot inputs for old generation tools | Rebuild/check the new access views from existing public records with standard-library Python; preserve old full-snapshot tools and their scope |
| Session templates and histories exist, but shared branch heads are not published | Immutable checkpoint records, small branch registry/views, expected-parent/revision checks, fork retention and explicit reconciliation |
| Primitive exploration has no dedicated shared record | Optional candidate template extending existing representation contracts; independent origin requires no prior card or gate |
| Existing candidate bridges have 25 unresolved legacy filesystem paths | Canonical card paths plus original legacy paths, hashes, quote lines and current-status routes; all bridge statuses/quotes retained |
| Twelve generated cards contain literal prose newline separators | 29 exact display replacements in generated views with raw and normalized hashes; originals unchanged |
| Compact TV-risk cards do not specify normalization | Explicit unresolved semantic notice for N07/N30/N44/N71; no invented convention or theorem-strength change |
| Historical architecture/current-state documents contain earlier counts and restart wording | Entry point directs current inventory/status/heads; historical README/DESIGN bodies retained with scope notices; old receipts and ZIPs remain frozen |

Existing task-first routing, optional core, immutable originals, local symbol contracts, typed graph classes and scoped corrections were strengths, not missing features. A new ontology, global symbol convention, embedding service, custom server and synthetic mathematical encoding were rejected as unnecessary. No graph edge is upgraded to a proved dependency or established interface. Informal repeated M30 headings in the transfer-map prose remain historical headings, not unique machine IDs.

## Practical retrieval and composition

For a known card, one dossier read brings recorded corrections, dependency notices, gates/blocker routes and the historical card together. For an unknown task, a concept router and one letter shard expose candidate IDs; the agent reads only relevant dossiers and proofs. Lexical proximity is navigation only. The original topic/reviewed-card paths still work.

The generator emits 396 unique source-range views at this input, each with at most 32 KiB of source payload. Larger ranges retain a whole-source route to avoid arbitrary splitting. Dossiers retain complete recorded scopes; no mathematical summary is compressed into a private language. A local packet command rejects an oversized complete packet instead of truncating it. This changes available access structure; no quantified model-performance improvement was measured or claimed.

Composition uses the existing graph, frontier relations, lemma and bridge records. Optional `agent/COMPOSITION.txt` separates proved dependency, established interface, candidate connection, incompatible assumptions and refuted transfer. It requires paired domains, norms, quantifiers, information acquisition, precision and complete costs. It does not assign these states automatically from topic similarity.

## Shared activity and discovery freedom

Theoretical Pro, Natural-sciences Pro, Ultra and Primitive Genesis use separate branch IDs; other instances use `worker-<slug>`. The initial views say UNPUBLISHED rather than fabricate active objectives from old manuscripts. A branch needs to publish its first observed research position. A reader follows the registry to one branch view, then the exact checkpoint contract when needed.

A writer publishes new artifacts and an immutable checkpoint with exact hashes, base revision and expected head set. Stale publication is rejected. Independent Git merges can retain multiple heads as CONFLICT; a new reconciliation references all heads. Git-local atomic publication prevents partial records. Remote main still requires a real fetch/recheck. Web conversations can retrieve/draft, but actual GitHub publication or an explicit writer handoff is necessary for synchronization. Timestamp order never selects a scientific winner.

The optional obstruction atlas projects existing gates/blockers, preserving their scope and incompleteness. Primitive records also permit independent invention with no indexed predecessor or discipline. Definitions are assessed through consistency, substantive consequences, theorem obligations, counterexamples and prior art, not names.

## Integrity, scope and follow-ups

The deterministic release checks cover card/status/catalog and lemma-sidecar agreement, all old manifest routes, exact source hashes/lines, generation reproducibility, incident-edge preservation, normalized displays, legacy CLI commands, UTF-8 packet refusal and checkpoint publication/concurrency/immutability. They do not replay scientific scripts, certify proofs, establish novelty or compare models. The final PR receipt records actual outcomes.

No original card, source, manuscript, package, dataset, code, failed argument, source snapshot or old audit receipt is changed/deleted. New excerpts duplicate only small selected indexed passages; they do not duplicate large original archives. Status ledgers and graph records remain unchanged. Original historical state files are retained.

Remaining high-value work is substantive: publish real initial branch checkpoints, repair/clarify the four TV interfaces from full sources, and curate missing exact claim-to-proof mappings and source-supported compatible interfaces. The corpus is not exhaustively audited for notation or dependency correctness. Lexical routing can miss non-ASCII vocabulary or unknown synonyms; concept invention deliberately remains outside it. Optional future archive repackaging can include new views, but preserved earlier exports are not falsely declared current. Full cold-source reconstruction still requires the original larger snapshot. No service or scientific validation is promised by this architecture.
