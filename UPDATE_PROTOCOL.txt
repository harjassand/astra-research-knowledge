UPDATING ASTRA | source preservation and scoped publication

Keep original source snapshots and their hashes recoverable. New bytes require a new immutable object/version; aliases of existing bytes remain aliases. Never rewrite original proofs, failed arguments, datasets, manuscripts, code or receipts. Stable card IDs persist. If inputs, quantifiers or claim strength change, add a version and scoped evidenced relation instead of silently strengthening a card.

Research proceeds independently of publication. For a selected meaningful result, scoped correction, decisive negative or usable handoff, the short route in state/PUBLICATION.md writes the existing checkpoint format. Preliminary files remain in the research workspace or ignored .astra-local/. No new card, bridge, gate, SESSION or workflow observation is required for every run or selected handoff.

When choosing a full canonical mathematical intake, record exact statement/assumptions, proof spine, costs, information-acquisition boundary, obstruction, comparator, missing lemma, source version and actual read/review depth. Update indexes/claims.jsonl and the existing CURRENT_CLAIM_STATUS record/sidecar together when changing canonical claim authority; proof availability remains separate from reported validity. Add reciprocal material_updates for affected earlier cards. Invalidate only the relevant downstream scope, never every topically similar result. Newer does not mean certified or universally superseding.

Original full-snapshot catalog/frontier builders require private SQLite/evidence unavailable in this public export. Do not pretend those tools rebuilt it. Public projection command: python3 frontier/build_access.py build. It consumes current public authoritative records, checks card/status/catalog agreement and recoverable source hashes, then generates concept shards, dossiers, connections, gate/blocker/bridge views, exact bounded proof ranges and counts. python3 frontier/build_access.py check detects stale inputs/outputs and regeneration differences. Scope/version information is retained; no scientific scripts or model calls run.

After intake, refresh existing topic/review routes and navigation manifest together. Run relevant deterministic source/link/hash checks, retain failures and old receipts, and inspect affected corrections. agent/CURRENT.txt is the current generated inventory; old validation reports and exported archives apply only to their recorded snapshot. A source access issue remains explicit and prevents a substituted proof excerpt. Generated routes may not disappear without an explicit compatibility migration.

Shared handoffs are separate from permanent evidence and current researcher activity: state/CONTINUITY.md gives append-only checkpoints, stale-parent/revision rejection, explicit concurrent-head reconciliation and real GitHub publication. Publish selected artifacts with hashes; do not overwrite historical state or previously private research without explicit disclosure approval. Web-only conversations can read/draft but need a real writer to synchronize. Check remote main before integration, work on dedicated branches and never force-update shared history.

Keep evaluation registrations/failures frozen. Navigation, source hash agreement, finite diagnostics, internal reviews and checkpoints do not certify mathematics, priority, empirical discovery or model performance. UNKNOWN stays UNKNOWN. Detailed research procedure: agent/RESEARCH_WORKFLOW.txt; paired composition requirements: agent/COMPOSITION.txt.
