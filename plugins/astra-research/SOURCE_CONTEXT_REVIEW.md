# Versioned source context delivery

The actual installed channel-proof route at PR256 returned305,775bytes over
13pages for a1,667-byte governing passage. Its35same-artifact citing records
repeated large current notices. The proof and selector were correct; this was
a response-size/navigation failure,not a new scientific result.

The generated release now declares `linked-current-capsules-v1`. A source keeps
its exact passage,source specification,artifact hash/selector and all citing
record IDs/content versions. Each record has its current-capsule fetch handle
and outer notice count. Complete conditions,corrections,gaps and scoped reviews
remain in that capsule. Read it and every continuation before using its result
as a premise. Same-artifact citation is navigation,not claim-specific support
or an acceptance transfer. Binary originals retain their original boundary.

The selection comes only from an output declared in the validated immutable
manifest. A missing layout field selects the original inline codec;an unknown
layout fails explicitly. Older `source`,`record`,`current` and `history`
handles keep their existing payloads. The ordinary build/check sets this
snapshot layout without a new scientist or curator field.

Known historical continuations now share the advertised30-second request TTL.
An unknown handle version still forces a published-release check so a newer
server's handle can become current before that TTL expires. Tests cover both,
exact historical payload/correction routes,marker selection,unknown-layout
failure,high artifact fanout,binary boundaries and real source/current capsule
qualification. No scientific source program is executed by this change.

Publication still requires actual-base CI,exact-head integration review and
verified public links. Actual installed source use must read the linked current
qualification,complete source passage and old handle continuations. The earlier
ordinary-intake automatic refresh must close before this reviewed runtime
