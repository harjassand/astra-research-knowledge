# Research to technology workflow

1. **Select an opportunity.** Define a real capability, user and measurable target.
   Retrieve only relevant current dossiers and decisive source ranges. Pin the
   revision. Cite the best-known comparator and its operating regime, or mark
   it unknown pending primary-source review. Assess significance conditionally;
   select further work by its route to a decisive result, not paper count.
2. **Invent a mechanism.** State the causal or computational operation and closest
   competent control. A high-impact hypothesis can be worth pursuing while its
   scientific status remains untested. Build a paired transfer contract before
   treating existing mathematics as applicable. Mark missing lemmas and services.
3. **Model.** State governing equations, information interfaces, units, constraints,
   precision and complete resource boundaries. Check conservation, thermodynamics
   and achievable material parameters when physical. Separate supplied-model
   mathematics from acquiring, preparing, decoding and checking that model.
4. **Simulate.** Freeze a decisive-test contract before optimization: prediction,
   equipment/data, controls, signal, uncertainty, estimated cost, acceptance and
   falsifier. Preserve code/input/output versions and failures. A producer-run
   simulation is computational evidence only. Reproduction records operator
   relationship, exact output/data references and an independence receipt.
5. **Validate experimentally.** For software, use an independent benchmark of the
   claimed interface and matched accuracy/resource boundary. For physical/hybrid
   mechanisms, obtain independent measurements in the relevant environment,
   including controls, calibration, uncertainty and raw-data provenance. If a
   laboratory is unavailable, retain a credible plan and the open gate. Equipment
   absence does not refute the mathematics. External contact, spending, private
   data transfer and experiments require their own actual authorization; this
   record is not authorization to perform them.
6. **Prototype.** Demonstrate the complete claimed function with reliability,
   tolerances, acquisition, preparation, control and operating resource charges.
   Record independently attested acceptance evidence. A component experiment
   does not establish an integrated prototype or deployable system.
7. **Assess scaling.** Evaluate manufacture, materials/supply, energy, economics,
   maintenance, environment and operating limits against a sourced competitor.
   Record demonstrated-system evidence separately from forecasts. The scaling
   gate does not authorize deployment or certify commercial viability.

At every step, record what is established and the next decisive unresolved
obligation. `stage` records completed gates; proposed next work belongs in
`next_obligation` and the experiment plan. Do not promote stages automatically.
Use `disposition=paused` for a resource wait. For abandonment, preserve the exact
failed mechanism, surviving scope and hashed evidence. A missing instrument or
an unproved transfer is not an executed counterexample. New counterexamples can
be valuable outcomes even if they end the motivating technology direction.

## Branch handoffs and prompts

Load `routes.tsv` only when a cross-branch obligation exists. Route a reverse
problem with its exact domain, quantifiers, access model, target precision,
permitted resources and proof/counterexample acceptance condition. Preserve
the destination branch's current heads. Scheduling and independent scientific
review are separate actions. A same-conversation continuation, another worker
with the same evidence, or an AI reviewer is not independent experimental review.

A task prompt can stay short: “Use the latest version of record X and only its
relevant current source notices. Address obligation Y under the paired contract.
Freeze the control, falsifier and cost boundary before the check. Return exact
artifacts, scoped result, failures, unresolved assumptions and next decisive
step. Preserve the source claim statuses.” For autonomous foundational work,
omit any demand for an immediate technological application. Sol Ultra can
reallocate workers to important opportunities while Pro branches retain their
own objectives; this implementation itself uses no workers or model trial.

Record the exact initiating prompt, available research context, model settings,
reported inference duration, actual usage receipts, output and verification in
the optional [workflow trace](../evaluation/workflows/README.md). Unknown facts
remain unknown. A retrospective trace does not substitute for a frozen matched
comparison or justify a meta-prompting advantage.

## Exposed end-to-end fixture

[`fixtures/contraction/record.json`](fixtures/contraction/record.json) connects an
elementary exact recurrence to a hypothetical software termination scheduler.
The paired interface explicitly requires a supplied contraction bound. The exact
finite run uses four updates; the equally informed stopping control also uses
four. The weaker ten-step reference is retained without claiming an advantage.
Neither total cost nor energy is measured.

The record reaches the scoped simulation gate. Its independent benchmark gate
is open. A forward handoff asks Foundry to validate matched total costs; a reverse
handoff asks theory for affordable certified-bound acquisition or a scoped
impossibility. No external request is sent. Mutating this fixture to claim an
experiment, prototype or system without the required evidence is rejected by
the deterministic tests. Later gates remain planned obligations, with no
invented measurements or manufactured independence receipts.

## Public repository boundary

Only cleared public architecture, published/publicly authorized evidence and
explicit synthetic fixtures belong here. `disclosure=public` is a required
record assertion; the validator cannot determine patentability, ownership,
consent, export restrictions or whether arbitrary prose contains a secret.

Keep confidential or potentially patent-sensitive mechanisms, private datasets,
credentials, lab notes and unpublished invention details in an access-controlled
store **outside the checkout**, including outside ignored and untracked folders.
Do not publish private paths, filenames, revealing hashes or speculative technical
disclosures as demonstration data. If needed, publish only an authorized redacted
capability-level lead with missing details explicitly unknown. Public references
must resolve within this repository; these tools never import private files.

Before committing, inspect the diff and reference targets for disclosure. Keep
the exact original bytes of authorized sources; changes need new artifacts and
versions. Existing source intake and preservation protocols remain authoritative.
