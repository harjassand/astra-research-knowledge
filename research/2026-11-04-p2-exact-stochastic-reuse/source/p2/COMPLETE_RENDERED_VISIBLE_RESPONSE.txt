Result: exact stochastic reuse has an information-dependent boundary

I completed a mathematical characterization of how much an actual stored random outcome can be preserved when its generating law changes, together with optimal sampling algorithms for a stored bit.

The useful organising concept is implementable overlap: agreement between two distributions that can actually be produced through a specified information interface, with its sampling costs included. Ordinary distributional overlap does not determine this quantity.

Two consequences are sharp:

For general distributions, universally exact reuse through independent sampling is limited to their common atoms. Even when two continuous distributions are identical, the old value cannot be retained with positive probability under this information contract.

2. General theorem: exact reuse is limited to common atoms

Let the state space be standard Borel—for example, a finite set, the real line, or a Euclidean space. Require exactness for all probability laws on that space.

Universal selection theorem

Every universally exact procedure that terminates after finitely many queries almost surely must return a value that actually appeared among its target-source draws.

This is a restriction derived from exactness; selection from the observed target samples is not assumed in advance.

The proof uses finite transcripts. Suppose a procedure sometimes stops and returns a value absent from its target-query list. Some finite query sequence has this property with positive probability. Fix a corresponding tuple of source values for which a positive-measure set of auxiliary random seeds produces that behaviour.

Now choose a finitely supported old distribution containing the old values in that tuple, and a target distribution supported exactly on its queried target values. The same finite transcript and seed event have positive probability under these distributions. The procedure then returns a value outside its target distribution’s support, contradicting exactness.

The argument allows adaptive querying and stopping. It even allows infinite expected work, provided every run still terminates almost surely.
