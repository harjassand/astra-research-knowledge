## Asymptotic and error accounting

The positive builder charges the supplied expression and its expanded output:
O(p+n+m) arithmetic/storage, where p counts actual production applications.
Repeated child IDs in a compact specification mean disjoint copies; exponentially
large output is not claimed producible in compressed-input time. No unary series
nodes are allowed. The source algorithm uses an explicit stack.

For fixed q=3, full decoder preparation and each decode are O(nq+m) arithmetic
and storage. Actual sparse action acquisition is O(n+m) per fixed number of
columns; an external oracle's measured action cost would be additional. No
graph-recognition or decomposition-finding runtime is silently assumed.
Exact rational bit complexity is additional to arithmetic counts. The saved
receiving residuals are exactly zero; a floating implementation must pay its
verified residual and acquisition/rounding errors as stated in PROOF.md.

The original dense NIST incumbent is not compared with these synthetic sparse
