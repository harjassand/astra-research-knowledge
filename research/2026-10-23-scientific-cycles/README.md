## Public edition and executable evidence

The selection retains mathematical source, implementation, supplied inputs,
recorded outputs, scientific reviews and corrections, resource records, and
scoped failures. Inherited ZIPs are unpacked once or linked by their exact
identity to another source directory. Git retains equal payloads as equal
blobs; historical owner and receiver paths remain available for source reading.

Private transport coordinates in selected text are replaced with the literal
`PRIVATE_DELIVERY_REFERENCE_OMITTED`. Those files are explicitly marked
`public_edition`, with original and public hashes and redaction counts. Other
selected payloads are byte-identical. No scientific expression, parameter or
recorded result is intentionally changed. Original private archives remain
preserved; this selected edition is not claimed to reconstruct their ZIP bytes.

Native statements such as “private delivery”, “not integrated” or “no public
publication” describe those dated source checkpoints. They are preserved as
historical evidence, not the current GitHub publication state. Use this return
and the actual PR/main history for current routing.

Omissions include private Page/chat/delivery and publication administration,
assignment prompts, caches, archive-directory downloads, rendered documents,
and downloaded paper/web copies. The member bindings identify all omissions,
including originals with the same name but different bytes. Bibliography and
source identities remain where supplied. Third-party code and data retain
their supplied attribution/license records; inclusion does not claim Astra
authorship. Follow those original records for reuse.

Use the owner-specific contracts, requirements and source paths when planning
an execution. For example, the latest Pro2 operation includes its fixed
certificate, native loader, graph inputs, exact decoders and recorded noise
checks together. Failed closure searches and rejected physical trajectories
remain evidence of their stated failure only. Owner `reproduce` scripts may
perform scientific calculations; publication has not rerun them. Native
whole-package verifiers and hard-coded native filesystem routes describe the
original environments and may require omitted administrative files or the
original ZIP. Do not treat them as certification of this selected edition.

For a read-only integrity check of the selected public payloads:


That command checks member hashes, safe paths, predecessor links and source
coverage. It never imports or executes the scientific implementations.
Repository validation uses the existing `state/check.py` workflow. Its success
and GitHub merge establish publication integrity, not scientific truth.
