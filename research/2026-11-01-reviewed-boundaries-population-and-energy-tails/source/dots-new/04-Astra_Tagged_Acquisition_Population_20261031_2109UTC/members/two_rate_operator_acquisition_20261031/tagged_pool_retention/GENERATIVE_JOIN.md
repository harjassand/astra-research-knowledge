# Historical missing metadata and prospective exact joint retention

The historical `RoutingSource.pooled_batch` does **not** retain source-row
identities. It integrates the uniform source row into a single destination
marginal and samples only pooled destination counts. No historical row tags
can be reconstructed from that file, and none are invented here.

The real named-row interface permits the learner to choose the row and observe
the destination label. A prospective method therefore receives BOTH the pooled
microscopic destination counts and source-row -> destination-BLOCK counts with
O(nr) extra streaming counters and no extra forward call. Ordinary competitors
receive the same metadata. This changes prospective acquisition comparisons;
old sufficient ledgers were never lower bounds.

`joint_source.py` generates new joint sufficient statistics, not independently
sampled marginals. First it draws all uniform source-row choices (counts N_i)
independently of outcomes. For each row it draws mixture-branch counts. Local
neighbor counts are generated jointly as a degree-sized multinomial and added
to both retained statistics; deterministic global-branch destinations likewise
update both. Macro and reset destinations are **actually sampled individually**
and their same labels update both statistics. Conditional on source/branch
counts this is exactly the same joint law as repeated ordinary transitions;
summing over those counts proves the unconditional iid pooled law. Cross-table
block totals are checked exactly. Aggregate simulation saves time, not logical
source calls. The number of actually generated macro/reset destination labels,
row multinomials, counter work, retained bytes and elapsed time must be charged.

The prototype uses power-of-two source blocks and local degree. Its first three
branch probabilities are exactly the binary64 argument values used by the
original `_row_counts`; the fourth is the remaining rational mass. Uniform
within-row groups and neighbor slots are generated by integer indices or exact
dyadic multinomial arguments. Thus its ideal argument-law model is the original
ordinary `_row_counts` law, not a silent conversion of the old separately
normalized `row_block_batch` / `pooled_batch` laws. Old column/coarse data used
that ordinary branch law and can still serve as previously paid discovery/
column evidence. Historical pilot/incoming/pooled marginals are NOT silently
joined to these new tagged rows. PRNG ideality and provenance remain external
premises, as elsewhere; this is exact joint-law construction, not proof of a
physical random source or numpy implementation.

Conditional on the independently chosen row counts, each retained row's
outcomes are iid with sample size N_i. The new scalar incoming witness argument
uses the fixed true maximizing row's confidence event, with its own N_i; a
conservative implementation can use N_min=min_i N_i in its radius. It must
refuse if a required row has insufficient observations. It cannot simply reuse
the equal-N historical proof. The outgoing pooled estimator remains iid
unconditionally; joint validity of outgoing, fine and row events uses a union
bound, not a false independence assertion between these correlated statistics.

## Full-record normalization and current result

For probability rows b and p and any continuation v in [0,1]^r,
|(b-p) v| <= ||b-p||_1/2. The current tagged receiver therefore uses the
sharper fine contribution Ld/2 rather than the conservative Ld in the earlier
supnorm prototype. All other terms and confidence events are unchanged. This
is a deterministic TV normalization, not another statistical trial or a
changed source. Pre-refinement source/results are preserved explicitly.
All three new rounds were actually generated and remain charged even if the
first-admissible prefix for a .05 request is earlier; a prospective stopping
comparison is not an actual-cost refund.

The final source helper guards integer labels, power-of-two blocks/degree and
counter index ranges. Its last branch argument is now explicitly set to the
exact representable remaining dyadic mass. Full regeneration verifies that
this changes no saved count at all. NumPy's primary API reference documents
its multinomial argument convention, but we still do not claim verification
of its random-bit implementation:
https://numpy.org/doc/stable/reference/random/generated/numpy.random.Generator.multinomial.html
