This standalone author candidate addresses the full square-free reversible binary
one-port hub architecture with every satellite covered by an arm. The proposed
conclusion is nonexplosion, irreducibility, positive recurrence, and **one explicitly
acquired nonzero exponential stationary total-count moment**. It is not an all-t
moment theorem or an arbitrary weak-reversibility result. No operational chemical,
biological or hardware claim is made.

## Mechanism

`THEOREM_PENDING.md` contains the complete proof and receiving argument. A genuine
sum of all independent-face rational tails is glued by an acyclic proper-subset
transfer, not max/min profiles or cutoffs. The tilt is chosen small after all
weights. An inactive-state indicator pays immigration there; its only adverse
entrance is last-A death, paid by the actual O(N) support-face capture reserve.
All other profile-death costs are paid either by the large-subset capture reserve
or by an explicitly bounded interior residual. No uniform occupation clock,
stationary fiber law, uncharged seed failure or deterministic-permanence premise
is used.

## Acquisition and actual cost

Raw architecture recognition is a finite channel scan plus positivity, reversibility,
coverage and shape checks. Quantitative construction explicitly examines 2^n masks;
there is no supplied independent-set oracle. `K^(n-|I|)` and selector constants are
actually computed integers/rationals. The fixture has 11 faces, 32 masks, maximum
reported scalar size 1,241 numerator-plus-denominator bits, and a 34,777-byte exact
certificate. Those measurements are fixture-specific, not complexity claims.

The last-death threshold uses `dA=1/[8(3M+1)^2]`, avoiding a gratuitous q^(3M)
expansion in scalar acquisition. CF and its stationary-moment bound retain the
finite exact power `t^(Nstar+1)` as an expression. The budgeted evaluator refuses
the fixture's enormous power rather than pretending to materialize it.

The low-level `profile(max_power=...)` budget counts exponents, **not bits**. A
power's numerator/denominator size is bounded by exponent times the corresponding
base bit size; `api.pointwise_profile` checks that separate bound. Subsequent
rational addition, multiplication, gcd and serialization also cost time/space.
No practical head size or efficient full-Lyapunov evaluation is claimed. The
interval test replaces enormous q powers by a rigorous q^M>=2 remainder bound,
with an explicit 8,192-bit truncation budget.

## Additive code repair after independent audit

The original manifest887f0cb1 and all its bytes remain untouched in the original
folder; its manifest is additionally preserved in `history/`. This repair does not
alter the governing theorem hashdc962264. It fixes three actual code/API defects:
1. Valid large rational input no longer trips Python's decimal-digit conversion
   guard while hashing or serializing. Integers/rationals above4,096 bits use
   explicit exact hexadecimal tags; the process-wide guard is not changed.
2. Internal channel rows are canonically sorted, making canonical certificates
   invariant under raw ordering and split duplicate-channel representation.

3. Canonical receiving uses recursive exact-type comparison, rejecting Boolean
   or float substitutions that Python's ordinary numeric equality would admit.

`check_repair.py` exercises a 2^20000 birth rate, exact JSON round trip and tagged
expression receiving, shuffled raw order and split duplicates. Full author tests
are rerun on these new bytes. This remains pending fresh independent receiving.

`raw_sha256` is retained only as a legacy alias for the explicitly named
`normalized_reaction_sha256`: sorted, duplicate-aggregated channels with exact
rational rates. `input_list_sha256` is a separate hash of the ordered parsed input
list (preserving row order and duplicate splitting), exposed by the qualitative
API envelope, not inserted into the canonical normalized certificate. It is not
a hash of original file bytes. Thus source provenance and normalized equivalence
are not conflated, and a reordered list may have a different input identity while
receiving the same normalized certificate.

The repair also reuses the retained-clock v4 finite-tree receiving guard as
ordinary capital (`certificate_guard.py`), with no ignored diagnostic subtrees.
Depth, visited nodes, scanned keys and pending nodes are charged before queueing;
cycles and shared mutable subtrees are refused before canonical production.
Exact-type equality itself is iterative. `check_guard.py` covers depth boundaries,
wide and aliased inputs and verifies malformed claims never reach the producer.
Guard refusal is a computation/representation result, not a stability statement.
