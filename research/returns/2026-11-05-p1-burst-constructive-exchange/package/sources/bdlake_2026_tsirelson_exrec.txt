L714@P17: generalizable proof that makes use of the extended rectangles formalism, which was also originally
L715@P17: used to provide a simpler proof of fault tolerance for the concatenated code scheme [22]. Before
L716@P17: proceeding with the proof, let us provide some informal intuition for why Tsirelson’s construction

L718@P17: First, we need a more general discussion of stable cellular automaton dynamics. In order to
L719@P17: stabilize a certain logical state, such an automaton must be able to correct domains of errors
L720@P17: created by the noise. For a generic configuration of noise, the largest spatial domain of errors
L721@P17: observed at any given time can scale with the system size L as ∼ log L, which diverges as L → ∞.
L722@P17: In two (or more) dimensions, there exist ways of locally correcting these large domains quickly
L723@P17: enough. One way is to use Toom’s rule [14], which shrinks domains in a time proportional to their
L724@P17: linear size. The reason this can be done locally is because boundaries of error domains form loops,
L725@P17: and the curvature of these loops can be determined locally.
L726@P17: However, in one dimension, an analogous rule is not possible given that boundaries of error
L727@P17: domains are point-like (this is also the reason why there are no ordered phases in 1D classical
L728@P17: locally-interacting systems in equilibrium). Thus, Tsirelson’s automaton must operate based on a
L729@P17: different rule: rather than trying to shrink domains of errors, it instead operates using a “divide
L730@P17: and conquer” strategy. The only error domains eliminated directly by the automaton are those of
L731@P17: length 1 (which are cleaned up by local majority votes). Larger domains, instead of being directly
L732@P17: shrunk, are instead fragmented into smaller domains which are then isolated from each other.
L733@P17: These domains recursively continue to be fragmented and isolated until they become small enough
L734@P17: to be directly corrected (see Fig. 1).
L735@P17: Consider first how the gadgets operate at low levels. Every operation X1 consists of a Z0
L736@P17: followed by three columns of X0. This means that X1 takes three bits as an input, computes their
L737@P17: majority vote (i.e. error corrects), and then broadcasts this value to all three outputs. Y1 starts
L738@P17: by applying a Z0 to two blocks of three bits, and then swapping both blocks. This is equivalent
L739@P17: to implementing a fault tolerant swap operation on a pair of encoded bits. Finally, Z1 starts
L740@P17: with applying Z0 to three blocks of qubits and redistributing the output via swaps so that each
L741@P17: output block contains one bit from each input block. As an explicit example, consider the action
L742@P17: of a clean Z1 on the input state ‘000 101 000’. Applying majority votes (Z0 gadgets) turns this
L743@P17: into ‘000 111 000’, and the redistribution performed by the pattern of swaps then turns this into
L744@P17: ‘010 010 010’. The action of Z1 thus fragments the minority domain of errors into three pieces,
L745@P17: which are distributed among each of the three output blocks. Following this with a final layer of
L746@P17: local majority votes (Z0 gadgets) completely eliminates the minority domain.
L747@P17: The elimination of errors at larger scales occurs in a self-similar fashion, repeating the same
L748@P17: action at each scale recursively (‘hierarchically’). An illustration of how an input error configuration
L749@P17: gets self-similarly cleaned up at level 2 is shown in Fig. 1.
L750@P17: 2.2 A modification of Tsirelson’s automaton
L751@P17: We will now introduce a minor modification of Tsirelson’s construction, which is readily amenable
L752@P17: to the extended rectangles method [22, 23] for proving fault tolerance. This modification also allows
L753@P17: us to define the notion of a fault tolerant simulation and interpret the action of the automaton as
L754@P17: repeated fault tolerant simulation of a 3-bit repetition code.
L755@P17: Each gadget in the modified automaton is analogous to a ‘gate’ from quantum computation,
L756@P17: with higher-level gadgets being defined in a way resembling transversal application of lower-level
L757@P17: gadgets:

L6979@P102: B Review of the extended rectangles (exRec) formalism
L6980@P102: In this Appendix, we will review extended rectangle method of Aliferis, Gottesman, and Preskill [22,
L6981@P102: 23, 10] for proving fault tolerance in concatenated code constructions. We want to start with some
L6982@P102: circuit C, either classical or quantum, and produce a ‘simulated’ version of the circuit F T(C). If
L6983@P102: each component in the circuit fails with probability p, then the probability that the output of
L6984@P102: the circuit C is wrong is large. We want F T(C) to have an error suppression property, where the
L6985@P102: effective error per component C will scale like O(p
L6986@P102: α) for α > 1 – then, recursively repeating this
L6987@P102: procedure will yield scalable error suppression. The way to realize the fault tolerant simulation of
L6988@P102: circuit C is by replacing it with a new circuit where each bit is now several bits and corresponds
L6989@P102: to a logical bit of a small code, and between each gate Gi and Gi+1 in the circuit (which is now
L6990@P102: an ‘encoded’ or ‘logical’ gate) one inserts an error correction unit which we will call EC. A layer
L6991@P102: of EC units are also added at the beginning and the end of the circuit. As a result, the simulated
L6992@P102: circuit is slightly larger than the original circuit.
L6993@P102: Both the encoded gates and the EC unit need to satisfy certain conditions. Before writing
L6994@P102: them down, we must define a notion of an r-filter and an ideal decoder. In particular, suppose
L6995@P102: the small code has the set of codewords S of some stabilizer code or classical F2-linear code on
L6996@P102: n qubits (or bits). For now, we will use notation consistent with that in Ref. [23]. We will also
L6997@P102: illustrate the concept with classical codes for simplicity, although the generalization to quantum
L6998@P102: codes is straightforward.

L7034@P103: Let us provide a bit of intuition for these conditions. For the Gate A property, we require that
L7035@P103: if an input state is conditioned on being r-close to a codeword, then a gate with s faults does not
L7036@P103: push the input state more than r + s distance from any codeword assuming r + s ≤ t. This does
L7037@P103: not necessarily require that the input state remains near the same codeword; in reality, it can jump
L7038@P103-104: Accepted in Quantum 2026-04-28, click title to verify. Published under CC-BY 4.0. 104to a different codeword so long as it remains close to one. The Gate B property implies that the
L7039@P104: input state undergoes the correct logical operation so long as it is sufficiently close to a codeword
L7040@P104: and the gate has few faults inside. The EC A property is perhaps the trickiest to satisfy: the input
L7041@P104: state can be arbitrary, but we require that the input state gets sent near a codeword under the
L7042@P104: EC unit, even if the EC unit has s ≤ t faults. However, the input state needs not to be mapped
L7043@P104: to the closest codeword, any codeword will do. Finally, the EC B property implies that if a state
L7044@P104: is almost a codeword and a faulty error correction operation is performed on it, the state should
L7045@P104: still remain close to the codeword so that it can still be properly read out by the ideal decoder. Of
L7046@P104: course, we demand the total faults r + s ≤ t.
