INTERFACE BOUNDARY

NativeSource alone owns a,b,alpha, hidden proposal choices, acceptance draws,
and nulls. PassiveObserver is constructed with n, integer R and the initial
state. Its on_change callback has only the new full state and timestamp.
No proposal label, accepted-channel identifier or null callback is supplied.
The observer uses actual changed support to distinguish single and double
jumps. Two different native channels that share a one-bit destination are
therefore aggregated, as required by the observation model.

The source is simulated by uniformization at rate 3n-2. Hidden proposals are
counted separately as computational simulation work; they are not treated as
observed statistical samples. The driver invokes the observer's own quota
timers before the next native proposal when necessary. Such a timer is entirely
determined by prior observed state changes and accumulated exposure. It reveals
no hidden source event: continuous observation already says that the currently
observed state has not changed before that timer.

EXPOSURE AND COUNT ORDERING

Each context stores its completed occupation and, when active, the beginning
of its current active sojourn. Its deadline is start+(R-exposure). A set of at
most m deadlines is updated whenever an actual change affects that context.
Thus there is no accumulation of stale per-event timers.

At an actual change time the observer first completes all quota deadlines
already reached, then counts the jump only in a still active, unfinished
context, then updates contexts under the new state. This implements freezing
N_c at occupation time R. Events at exactly a real quota boundary have
probability zero in the ideal model; the code's deterministic tie convention
processes quota completion first. Different contexts can complete at different
times, and an already completed context never acquires additional counts.

For single-bit changes at i the context index is 2i+right, with the absent
right bit treated as zero. This agrees with the final site's single context.
Its activity mask enforces the selected old-bit direction and left neighbor0.
For a double jump the changed support must be exactly two adjacent sites; its
context masks enforce odd00 or even11 with existing outer bits0. The observed
support therefore identifies the desired cycle transition without a label.

The explicit physical cycle notation and the integer encoding agree:
old=x_i+2x_(i+1), forward={1,3,2,0}, reverse={3,0,2,1}. This was independently
checked against the rational aggregate-generator assembly in analyze_passive.py.

FIT AND MATHEMATICS

analyze_passive.fit uses only integer counts, R and n. All fitted a,b,alpha are
Fractions. Heatbath rates are clipped to[81/181,100/181] before parity-dependent
odds inversion. Shared b_i is obtained from two odds at one site. Even alpha
uses raw r_(i,1) and raw r_(i+1,0), then is clipped; it does not inadvertently
reuse factor-clipped odds and thereby claim the tighter error formula falsely.
All final factors are clipped to their known parameter domains.

The exact rational audit verifies stationary weighted column sums, all 864
selected aggregate intensities, and exact factor recovery, in each of the
true and fitted models. The rate identities are checked over every outside
configuration in the small model, so overlapping-cycle contamination would
be detected. The proof, rather than this finite fixture, establishes the
identities for arbitrary path length.

Dense killed linear solves are used only for the 256-state numerical evaluation.
Their residuals are reported, and the screened mean intervals are checked
against those ordinary direct solves. Source-transfer enlargement uses the
exact-family weight/flow theorem and its full conservative factor 67.45636543.
It is not the root's more general misspecified-generator certificate; that
certificate needs additional aggregate-rate acquisition not supplied here.

RESULT AND LIMITS

All 22 quotas R=200000 completed in one trajectory. The observer saw 25,773,891
actual changes over 3,269,831.650519209 native time units. The simulator executed
71,933,832 hidden proposals; it also generated one pending future waiting time
before stopping, so waiting-time draws number 71,933,833. Hidden proposal work
has not been omitted or relabelled as visible data.

Elapsed time is in native generator units, not host execution seconds. Host
walltime and CPU time were not recorded, and no hardware benchmark is asserted.
The output archive should retain the .cpp, .py, .txt and both .json files in
this directory. The compiled passive_native executable is platform-dependent
and should be excluded. No old research file was modified.

At eta=.02, the simultaneous ideal-model rate failure bound is .00606816361.
The largest measured rate error against fixture truth was .0074407. This is
inside the stated event, but is not substituted for a confidence bound.
The fitted/true mean ratios are .996272271377 and 1.000252595786 for the two
reported targets. The valid conservative intervals remain very broad.

The source uses a seeded mt19937_64 PRNG, long-double timestamp arithmetic,
and floating acceptance probabilities. It supplies a numerical diagnostic
trajectory, not certified exact random bits or a verified native clock.
No machine-checked rounding enclosure is asserted. PASSIVE_ACQUISITION.txt
separately proves an ideal exact-time statement and a finite-clock extension
requiring certified timestamp error and no missed or aliased event supports.

The history output preserves sufficient acquisition counts, quotas, full costs,
first 24 actual records and a noncryptographic checksum, rather than storing
every record. The source and observer are executable and seeded for reproduction.
The theorem does not require physical preparation of the simulator's chosen
initial configuration; it holds from any available observed initial state.

No substantive implementation error remains in the examined observation,
reconstruction, aggregate-rate identities or reported exact-family comparison.
This run demonstrates the observation interface and proof plumbing. It does
not demonstrate practical superiority, a high-precision rare-event forecast,
or validity under unobserved modifications of the known source architecture.
