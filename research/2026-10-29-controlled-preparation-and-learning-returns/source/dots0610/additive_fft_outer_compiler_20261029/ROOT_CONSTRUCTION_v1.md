# A degree-filtered additive Fourier compiler for the full-length CSS outer code
2026-10-29. Root derivation. Executable compiler and independent review pending. Classical additive FFT machinery is prior art; this is a proposed explicit quantum-control implementation, not a new FFT claim.

Let F=GF(2^h), B=2^h, with fixed binary field basis beta_0,...,beta_(h-1). Let W_j=span_GF2(beta_0,...,beta_(j-1)). Its subspace polynomial s_j(x)=product_(w in W_j)(x-w) is additive, of degree2^j. Normalize t_j(x)=s_j(x)/s_j(beta_j). The denominator is nonzero because beta_j is outside W_j. Thus t_j vanishes on W_j and t_j(beta_j)=1. For 0<=i<B, define b_i(x)=product_j t_j(x)^(bit_j(i)). It has degreei with nonzero leading coefficient. Consequently the firstk b_i span all polynomials of degree<k. This is the property the nested RS/CSS code needs; no expensive conversion to monomials is required.

Write f=f0+t_(h-1) f1, with lower-half coefficient vectors for f0,f1. At points x in alpha+W_(h-1), t_(h-1)(x)=c=t_(h-1)(alpha); on the opposite coset alpha+beta_(h-1)+W_(h-1), the value is c+1. Replace every coefficient pair(a,b) by (a+c b,a+(c+1)b), then recursively evaluate the two lower-degree polynomials on their respective cosets. Repeat to obtain all B field evaluations. The evaluation order is the fixed binary basis enumeration of field points.

Each butterfly is invertible in characteristic2 and can be compiled exactly as two in-place operations:
1. a <- a+c b, a constant field multiply-add.
2. b <- b+a, where a now means its updated value.
Their output is the desired pair. A known constant multiplication is an h-by-h binary matrix; adding it into a disjoint h-bit target uses at most h^2 CNOTs. The second operation uses h CNOTs. There are exactly Bh/2 butterflies. Thus a conservative CNOT upper bound for one encoder transform is B h^2(h+1)/2, no clean quantum ancilla beyond the B field registers. Reverse the elementary CNOT list for the inverse transform. Constant c=0 or1 gives cheaper butterflies; the executable compiler should count actual nonzero entries rather than only this upper bound.

For B=2048,h=11 the sufficient bound is1,486,848 CNOTs per transform, compared with the earlier generic dense sufficient bound exceeding500million for a nearby length2047 example. These are different length/basis implementations, so this is not a measured speedup of an unchanged executed quantum circuit. Field constants, classical compilation, classical decoding and storage still cost resources.

CSS encoding: choose C2=polynomials degree<2t evaluated at allB points and C1=degree<B-2t, with B>=4t. Prepare first2t field coefficient registers in uniform superposition, middle B-4t in the logical input, last2t in zero. Apply the additive evaluation transform. This gives the coset-superposition CSS code C2 subset C1 of dimension q^(B-4t) and distance>=2t+1. The basis being degree-filtered preserves the actual RS codes, not just an analogous code family.

Quantum decoding can first apply the inverse evaluation transform. For physical Pauli X(x)Z(z), field-linear evaluation L converts it to X(L^-1 x)Z(L^T z). Measure the first2t coefficient registers in the field-character Fourier basis and last2t in the computational basis. These are exactly the stabilizer syndromes; leave the middle registers unmeasured. A total bounded-distance RS classical decoder finds the unique error of weight<=t when one exists, otherwise uses a declared fallback. Compute its decoded-coordinate Pauli and correct the middle registers. There is no need to re-encode the recovered logical output. Correctness for coherent/memory-correlated errors follows from the same CSS Knill-Laflamme condition, not classical sampling alone.

In characteristic2, computational registers use the chosen polynomial basis and phase labels use its trace-dual basis. A bitwise Hadamard measures the dual character basis, but implementations must track this convention explicitly. Treating field multiplication transpose as ordinary multiplication in the same self-dual basis without proof would be an error. The executable check must verify both X and Z syndromes/corrections, including this coordinate issue.
