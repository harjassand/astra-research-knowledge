# FIRST_CONSTRUCTION — syndrome-adaptive QEC controller

## Candidate operation and resource boundary

The operation considered here is an online code-frame controller for a logical memory. During ordinary repeated stabilizer extraction, it reads the legal syndrome record, estimates a drifting local unital-noise orientation, and changes both the physical frame and the measured stabilizers so the code's larger distance protects the currently dominant error. Its output is the logical state after a run of memory cycles, with the controller's rotation and code-frame changes included in the executed circuit. It does not receive a supplied decoder or latent noise trajectory.

The minimum model needed to make that operation executable is a stabilizer code with known syndrome-extraction circuits; a parameterized local noise family; an identified map from frame setting to physical rotations and stabilizer measurements; and repeated syndrome records with a known time ordering. The controller also spends physical rotation/control pulses, changes the syndrome-measurement basis, stores and updates a parameter posterior, and incurs latency while estimates accumulate. It needs a noise-family promise: records alone do not identify an arbitrary channel. Logical output measurements used to evaluate lifetime are a separate diagnostic resource, not a free feedback signal.

For a concrete instance, take the asymmetric `[[15,1,7/3]]` shortened Reed–Muller code. In the convention of Florjanczyk and Brun, its correctable weights are up to three X errors and one Z error. Their controller estimates an unknown noise orientation from the syndrome-error counts, applies a common single-qubit rotation to the code block, and updates each check by the same conjugation,

\[
g_s\longmapsto U_t^{\otimes 15}g_s(U_t^\dagger)^{\otimes 15}.
\]

Thus a dephasing axis can be rotated into the code's higher-distance direction while the logical state remains encoded. This is a concrete closed control loop, rather than a decoder-only update.

## Decisive scope challenge: syndrome records cannot resolve logical cosets

An unrestricted syndrome-only controller cannot learn every logical effect of the channel. The three-qubit bit-flip repetition code gives an exact witness. Let

\[
S=\langle Z_1Z_2, Z_2Z_3\rangle,
\qquad
\sigma(X^{e_1}X^{e_2}X^{e_3})=(e_1\oplus e_2,\ e_2\oplus e_3).
\]

Then

\[
\sigma(X_1)=\sigma(X_2X_3)=(1,0),
\qquad X_1(X_2X_3)=X_1X_2X_3=\bar X.
\]

The ordinary recovery for syndrome `(1,0)` applies `X1`. Under the deterministic channel `X1`, the recovered logical operation is identity; under `X2 X3`, it is `Xbar`. Yet each stabilizer measurement returns exactly the same syndrome in both cases. Once corrected, the residual `Xbar` commutes with every stabilizer, so subsequent ideal syndrome rounds also have identical records. Any controller whose observations are only these syndrome records must choose the same actions in the two cases and cannot certify which logical channel occurred.

This does not contradict syndrome-learning theorems whose premises restrict the noise to a correctable class or a specified Pauli family. The pair deliberately places two errors in the same syndrome coset and their difference is an uncorrectable logical operator. A controller can break the ambiguity only by adding information such as a logical reference/input, a logical measurement, or a justified noise-family/correctability promise. Those are different access and cost assumptions. In particular, a syndrome-only signal-minimization reward can be blind to this logical failure mode; a separate logical-performance measurement is required to validate its objective.

## Prior-art gate and disposition

The chosen operation is already directly present in the primary literature. Florjanczyk and Brun's *In-situ Adaptive Encoding for Asymmetric Quantum Error Correcting Codes* (2016; arXiv:1612.05823v2) estimates an unknown unital-noise parameter from stabilizer syndromes, rotates the physical code block, conjugates its stabilizers, and updates online under a drifting parameter. Their example is precisely the `[[15,1,7/3]]` code above. Its lifetime gains are numerical results under their stated channel model, not a hardware demonstration. Consequently, the core proposed operation is not a new opportunity here.

The neighboring incumbent literature closes the generic variants as well:

- Wagner et al., *Pauli channels can be estimated from syndrome measurements in quantum error correction*, Quantum 6, 809 (2022), proves syndrome-based Pauli-channel estimation for arbitrary stabilizer codes under a correlation-order condition given by pure distance, including data-syndrome measurement error.
- Wagner et al., *Learning Logical Pauli Noise in Quantum Error Correction*, PRL 130, 200601 (2023), proves learnability of the logical Pauli channel from syndrome data when the code can correct the noise.
- Berthusen et al., *Adaptive Syndrome Extraction*, PRX Quantum 6, 030307 (2025), gives an adaptive check-scheduling scheme using a `[[4,2,2]]` inner code and a hypergraph-product outer code.
- Sivak et al., *Reinforcement learning control of quantum error correction*, Nature 655, 879–884 (2026), uses QEC detection events to tune more than 1,000 analog controls on Willow; the reported experiment improves logical-error stability by 3.5-fold against injected drift and includes decoder steering. It is a direct system-level incumbent for records-to-control operation.

The unresolved, narrower question would have to add a measurable capability absent from these works—for example, a new noise class for which intervention-conditioned syndrome records identify a physically actionable code/control choice, with a circuit-level advantage after code-switch, measurement, controller-latency, and reset costs. No such surviving candidate is established by this check. The present result is a scoped closure, not a claim that all future syndrome-driven control is exhausted.

## Supplemental bounded audit — coherent Hamming-labelled Pauli checks

This check was added after the first construction had been frozen. The separate proposal is to surround one known Clifford `U` with controlled-Pauli checks, assign the `3n` single-site errors distinct binary syndromes using a GF(4) spread, measure the check ancillas, and apply the indicated Pauli recovery. It targets a one-error operator span, not a continuously running encoded memory.

### Ideal algebra

For an `r=2m` bit syndrome, the nonzero vectors of `GF(4)^m` split into scalar orbits

\[
\{x,\omega x,\omega^2x\},\qquad \omega^2+\omega+1=0.
\]

Each orbit is one two-dimensional binary subspace with three nonzero elements. Assign one orbit to each physical qubit and label its `X`, `Z`, and `Y` errors by the three orbit elements, choosing `Y` as the binary sum of the `X` and `Z` labels. Distinct qubits receive disjoint orbits. There are `(4^m-1)/3` orbits, so `m=ceil(log_4(3n+1))` suffices and `r=2m` check bits. The `2^r` ancilla outcomes then distinguish identity and all `3n` weight-one Pauli errors.

If the noise is exactly a channel with Kraus span contained in

\[
\operatorname{span}\{I,X_1,Y_1,Z_1,\ldots,X_n,Y_n,Z_n\},
\]

and the pre/post check circuits and ancilla measurements are ideal, the syndrome is independent of the input state and separates each Pauli component. A conditioned Pauli correction therefore returns `U|psi>` on every branch. This is a valid one-error-span mechanism, including coherent linear combinations in that span. The count is also information-theoretically necessary for nondegenerate identification: `2^r >= 3n+1`, hence `r >= ceil(log_2(3n+1))`. The even-bit GF(4) construction is at most one bit above that counting bound.

### The construction is Hamming syndrome geometry

The GF(4) triples are the syndrome-column geometry of the standard GF(4)-Hamming stabilizer code: one parity-check column for a physical qubit and its three nonidentity Pauli errors produce exactly the three nonzero labels in that column's line. At lengths `N=(4^m-1)/3`, the corresponding one-error-correcting stabilizer construction has `2m` independent binary syndrome bits and encodes `N-2m` logical qubits. Thus the proposal uses familiar single-error Hamming packing inside a coherent check-sandwich implementation; the syndrome geometry itself is not a new coding mechanism. The exact Hamming-code lengths have slack for general `n`, and an encoded comparator pays for encoding and protected logical gates. The quantum Hamming count for a nondegenerate distance-three block, `2^(N-k) >= 1+3N`, is the same syndrome-counting constraint; it is not evidence that either circuit implementation is cheaper.

### Cost and failure envelope

Let the target circuit have independent nonidentity Pauli probability `p` on each of `n` wires *after the whole Clifford*. With ideal checks, the candidate corrects zero or one such fault. Its residual-error probability is bounded by

\[
P_{\ge2}=1-(1-p)^n-np(1-p)^{n-1}
       ={n\choose2}p^2+O(n^3p^3),
\]

whereas an unprotected output has error probability `P_{>=1}=1-(1-p)^n`. The apparent quadratic gain is real within that placed-noise model.

It is not yet a circuit-level advantage. A straightforward implementation uses one controlled-Pauli interaction per supported data wire for each pre- and post-check. With `G` such two-qubit interactions and per-interaction fault probability `q`, a conservative comparison that counts every check fault as harmful gives

\[
P_{\rm cand}\ \leq\ P_{\ge2}+1-(1-q)^G,
\qquad
\text{and a sufficient condition to beat the bare target is }\quad
1-(1-q)^G < np(1-p)^{n-1}.
\]

For small probabilities this requires `Gq << np`. If the checks are dense, `G=Theta(nr)=Theta(n log n)`, so a sufficient gate-quality window is `q << p/log n`; a wrong syndrome bit or a check-induced data error can itself cause a wrong recovery. This is a sufficient adverse-accounting bound, not a claim that every check fault is fatal. A measured circuit model could show that some check faults are caught or benign.

The particularly restrictive premise is noise support. If the physical circuit has depth `T` and faults can arise at many internal locations, a single fault propagates through later Clifford gates into one of up to `M` distinct output Pauli strings. The `3n`-label assignment does not identify this larger set. Correcting an arbitrary single internal fault requires unique labels for identity plus every distinct propagated fault operator, at least `r >= ceil(log_2(M+1))`; multiple faults have further collisions. In a full fault-tolerant computation, syndrome extraction itself is noisy, so one needs temporal redundancy and decoding of the space-time detector record, as in standard repeated-check codes. The one-shot wrapper does not supply that redundancy for free.

### Equally informed comparators

- The 2024 commutation-derived quantum-filter paper already gives deterministic correction for arbitrary errors in an `n`-qubit Clifford circuit using `2n` clean ancillas, and an ancilla-efficient two-ancilla Pauli filter that detects all weight-one components but does not recover every rejected branch. The present Hamming point is a plausible intermediate on ancilla count, but the primary paper also analyzes noise in the filter gates; clean initial ancillas alone are not an end-to-end noise model.
- Pauli Check Sandwiching (PCS) already implements pre/post coherent Pauli checks for arbitrary input states and Clifford circuits. Its published two-layer construction filters all weight-one Kraus errors in a postselected branch with `2n` CNOTs in the post-check components; it explicitly charges success probability and discards rejected runs. The proposal's possible delta is to use `O(log n)` syndrome bits to identify and correct a weight-one error instead of rejecting it, not to invent the sandwich.
- Coherent Pauli Checks (CPC) have been demonstrated on circuits with up to ten logical qubits and over one hundred logical CNOTs. CPC provides a close check-cost / connectivity baseline, but its standard task is single-shot error-mitigated output sampling, with logical-error suppression under its tested noise model.
- A quantum Hamming stabilizer block supplies the same single-error syndrome packing with protected logical qubits; a repeated surface-code or other space-time decoder supplies protection against faulty checks and faults across rounds. These encoded comparators pay encoding/decoder costs, but unlike a single sandwich they target sustained circuits and check noise.

### Verdict and decisive comparison

The syndrome map is algebraically sound for the stipulated one-Pauli-error span, and the correction-versus-postselection distinction is potentially useful. The current proposal is not yet an output-changing result beyond standard Hamming coding and coherent Pauli-check filters. Its decisive test is a matched noisy-circuit comparison on the same Clifford workload, using (i) this Hamming-labelled one-shot correction, (ii) PCS/CPC at the same ancilla and two-qubit-gate budget, and (iii) a fault-tolerant encoded comparator, with preparation, all pre/post check gates, readout, reset, encoding and run yield counted. The comparison must inject noise throughout the compiled circuit and check layers, rather than only after an ideal black-box `U`. Until that passes, the `O(log n)` ancilla count is a clean-ancilla/model-level point, not evidence of lower total cost or scalable fault tolerance.
