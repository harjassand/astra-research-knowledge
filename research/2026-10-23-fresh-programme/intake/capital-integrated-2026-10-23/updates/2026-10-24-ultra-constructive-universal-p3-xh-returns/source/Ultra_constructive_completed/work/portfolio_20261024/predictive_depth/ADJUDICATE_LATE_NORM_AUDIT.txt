1. Which exact identity the implementation uses

Use column-state convention. Let H be the TRUE core, G the TRUE shift/macro
matrix, A=Hhat, F=Ghat, B=G H^-1, and Bhat_raw=F A^-1. Then

 (Bhat_raw-B)H
    = Bhat_raw(H-A) + Bhat_raw A - G
    = (F-G) - Bhat_raw(A-H).

There is no approximation and no commutation. Therefore

 ||Bhat_raw-B||infinity
 <= [||F-G||infinity + ||Bhat_raw||infinity ||A-H||infinity]
       ||H^-1||infinity.

On the declared simultaneous event, ||F-G||infinity<=dz,
||A-H||infinity<=dH, ||H^-1||infinity<=Jbar. The implemented expression

   (dz + ||Ghat Hhat^-1||infinity*dH)*Jbar

is thus valid. The allegation treats it as an illicit substitution into the
DIFFERENT decomposition using Ghat times the inverse difference. That other
decomposition can yield the looser factor ||Ghat||infinity||Hhat^-1||infinity,
but it does not invalidate this exact residual identity. Replacing the norm
of a product by a larger product of norms is an optional loosening, not a
required correction. The proposed approximately 94.24 bound is consequently
not evidence of an error in 16.18; both may simply be valid bounds of different
tightness.

2. Actual raw/repair code paths

finite_predictive_learner.py first stores raw[a,o]=hz@inv, copies these matrices
to b, repairs ONLY b[a,1]'s causal row, and evaluates its uncertainty term using
raw[z]. It then adds ||b[a,1]-raw[a,1]||infinity. This is exactly the triangle
bound required for the repaired map.

direct_macro_learner.py first forms ops[b]=hz[b]@inv, changes only the abort
row, then RECOMPUTES raw=hz[b]@inv in its error loop. Its uncertainty expression
uses this raw matrix, and adds ||ops[b]-raw||infinity separately. No repaired
matrix is silently substituted into the raw identity. Its observed repair
is only 9.4368957e-16, but it is nevertheless charged.

3. Independent derivation of the tighter acquired kappa bound

For the r-by-r real inverse A^-1, the induced infinity-to-one norm is exactly

 khat=max_(s in {-1,+1}^r) ||A^-1 s||1.

Every point in the unit infinity cube is a convex combination of its sign
vertices, so the maximum over vertices is an upper bound on all cube points;
vertices themselves are allowed, proving equality. The code enumerates all
16 vertices for r=4.

The Neumann condition nu=||A^-1||infinity*dH<1 gives
 ||H^-1||infinity<=Jbar=||A^-1||infinity/(1-nu).
The exact inverse identity is
 H^-1-A^-1=H^-1(A-H)A^-1,
so ||H^-1-A^-1||infinity<=Jbar*dH*Jhat. Any r-row matrix E satisfies
||E||_(infinity->1)<=r||E||infinity. Thus

 ||H^-1||_(infinity->1) <= khat+r*Jbar*dH*Jhat.

All preparation states in this fixture are positive and normalized, hence
the physical quotient norm comparison has kappa no greater than this inverse
norm. The code's khat=23.30032757 plus 3.48145602 gives 26.78178359, a valid
upper bound. This does not use exact/private physical state information.

4. Pilot independence wording

The basis and its H calibration share ORIGINAL pilot counts. That is safe
because CountOracle's predeclared 1884-event confidence pool covers every
candidate core/shift event before selection. The pilot is independent of the
NEW macro data; its H is not independently re-estimated after basis selection.
The comment 'basis is fixed from independent pilot data' means independence
from macro data, not independence between the basis and H within the pilot.
This clarification changes neither probabilities nor error bounds.
