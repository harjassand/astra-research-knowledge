# Capital integration contract

An existing semantic notice may name `current_scope_unit` for a later scoped
construction. The same ordinary build validates that exact target and required
notice support; an unknown target fails ingestion. CLI/native search exposes
these explicit outlinks with the current target content version. Native routes
include a snapshot-bound fetch handle. Bounded previews state total/omitted
routes; fetch the candidate's complete notices for the rest. This navigation
neither changes ranking nor infers a compatible transfer, acceptance or premise.
No new producer metadata or reporting step is required.

The same build/check now generates lossless operation views and evidence
navigation from existing record citations and recognized selected-public-source
indexes (`astra.intake-source-index.v1`, `selected_frozen_source_index`, or
`astra.scientific-source-selection.v1`). The last format uses its explicit
`repository_path` relative to the index directory; `original_path` is provenance
and is never followed. Both `INDEX.json` and `SOURCE_INDEX.json` declarations
are discovered. Keep
using those existing formats; no producer form is required for intake.
Their explicit public entries must retain exact SHA256/byte length;
missing declared originals fail ingestion. Private `origin` paths are never
followed. Index admission gives evidence discoverability, not scientific
acceptance. Scoped extractions retain their cited-range boundary. See
`knowledge/current/coverage.json` for the exact admitted denominator/exclusions.

Current/historical review, correction and transfer citations enter that same
evidence view with their actual roles; indexing never inherits acceptance.
`coverage.json` lists each admitted index, exact original count and existing
source-version record contexts. Uncited originals remain a semantic-curation
gap; a file count is not result completeness. Original/read-path aliases at the
same path and byte hash share correction context without widening statement
support or conferring acceptance.
Read actual completed internal reviews and their reviewed-artifact versions;
external/formal next-gate boilerplate is not a prerequisite to scoped internal
acceptance. Keep genuine gaps and conflicting later source assessments visible.

1. Start from current merged main in your own intake checkout. Preserve original
   source bytes and stable result identities. Keep raw originals separate from
   derived text. Use existing claim/status/catalog/alias/notice shards; do not ask
   scientific producers for another form. Register new or revised support in the
   existing scoped frontier status sidecar and aggregate/shard together.
   If an immutable checkpoint pins a card/status path and hash, preserve the
   original at that path; archived copies elsewhere do not satisfy the pin.
   Carry a current change through immutable units and an explicit current
   authority/correction notice. Historical source labels remain history, and
   the current scoped premise must be clear without rewriting the checkpoint.
2. Read the decisive source passage and any substantive completed internal audit.
   Preserve quantifiers, supplied/acquired access, units, error and cost model.
   Record actual conditional internal acceptance at the reviewed source version
   and scope using a small curator-owned `knowledge/reviews/*.json` overlay;
   hashing, intake checks or a source's assertion of an audit are not themselves
   that audit. Do not require specialist/external review. Keep physical evidence,
   practical advantage, novelty, genuine gaps and unresolved imports separate.
3. A changed card, source, accepted subresult, correction or supersession uses the
   same path: `python3 knowledge/build.py build`, then
   `python3 knowledge/build.py check`. This normalizes all registered cards,
   existing atlas entries, reusable units, latest technology versions and cited
   source windows into one current corpus and regenerates packets, search
   postings, coverage, contextual operation views/vectors and manifest. No
   per-run manual tags are required. The free pinned local CPU runtime in
   `knowledge/requirements-agent.txt` infers only new or changed semantic text;
   unchanged vectors reuse exact model/protocol/text keys. Missing runtime for
   required new vectors fails ingestion instead of publishing stale views.
4. Reusable extractions are selective curator work, not a producer requirement.
   Add a stable ID under `knowledge/units/<ID>/v0001.json`, with exact supporting
   quote/range and a requirements/provides/assumptions/costs/units/obstruction
   contract. Changed meaning gets the next immutable version linked by the
   previous file hash. Existing `literature/LEMMA_ATLAS.jsonl` plus its sidecar is
   also an accepted input format; no duplicated scientific statement is needed.
   Read the actual passage, not just the title or stored hash. Bridges require
   exact endpoint content versions, cited argument, scope and remaining
   obligations; no bridge is inferred from topical proximity.
5. Run `python3 state/check_current.py --base-revision <actual-PR-base-SHA>` and relevant
   knowledge tests. Inspect the changed packet, follow its source route and read
   the affected passage. Repeat build/check once to demonstrate idempotence.
   Review and merge the focused PR under existing authorization. Return verified
   public links through the normal dispatcher route.

An ingestion error is a stop for that intake, not permission to share the old
generated views as current. Required support must be present and correct before
publication. Conflicting assertions remain separate, scoped notices; neither
chronology nor indexing resolves the science. Source revisions, historic cards,
old manifests and previous versions remain available. Producer research does
not wait for a programme-wide idle gate.

The contextual projection covers every current canonical record with two
deterministic statement/input/output and condition/obstruction views. It is
generated by that same build/check, using the shipped public BGE encoder and
no paid endpoint or private database. Cache reuse verifies prior output hashes,
finite unit vectors and exact text/model/protocol identities; current record
and operation-frame versions are regenerated even when vectors can be reused.
The published corpus identity also covers exact vector bytes, so differing
numeric projection bytes cannot silently share one served corpus version.
New/deleted records, corrections and supersessions therefore change current
membership through ordinary intake. All original source/support checks run
before this projection. Fully built portable CLI/web reading remains stdlib.
The512-token view limit is a relevance limit; complete assumptions, costs,
units, corrections and governing sources remain in the current packet.
The ordinary release also declares its source text projection automatically.
New releases distinguish notebook-shaped cells from detector or scientific JSON
cells. Historical snapshots without that marker retain their original decoder
and source payload bytes. Unknown or stale markers fail explicitly. No producer
annotation or extra intake step is required; a reader-code change still needs
its reviewed deployment before the new release can be served.

## Optional named consumer inputs

A curated reusable unit may declare `contract.input_slots`, each with an `id`,
description and `required_binding_fields` (including `units` and
`qualification`). A version-bound `ESTABLISHED COMPATIBLE INTERFACE` transfer
may add `slot_binding`: the declared slot plus its explicit field values.
The transfer still needs its actual supporting proof passage and remaining
obligations. Other transfer states cannot silently become typed providers.

The ordinary build generates `interface_navigation` in canonical records:
bindings once on the consumer and routes on the exact provider and its parent.
Missing fields, unknown/ambiguous slots and stale endpoint versions fail
ingestion. Common-consumer peers are navigation candidates; no transfer between
providers or inherited acceptance is generated. All qualifications, costs,
corrections and field-specific acquisition obligations remain. These optional
annotations are intake-agent work for selected useful interfaces, not a new
researcher form or a requirement to classify every source.

Large packets may omit optional navigation excerpts whose complete locators
already occur in `evidence`. Exact duplicate legacy gap citations can use the
existing `evidence_ref_indices` convention; `evidence_ref_annotations` retains
any original per-source metadata. The actual gap scope and every correction,
condition and review remain. Conflicting references are kept separately.

If complete transfer mappings overflow the default packet, an identical full
citation already retained elsewhere in that packet may be represented by
`evidence_ref_pointer`, a standard JSON Pointer resolved against the ROOT
packet. Resolve it in place in the evidence list, retaining order. The pointed
object includes every original quote, source scope and annotation; different
locators or qualifications stay separate. Unique provider citations remain
inline. Every mapping, condition and correction is retained; shared citation
storage confers no acceptance or additional statement support. Canonical
transfers stay complete.
The same pointer convention may share identical citations in transfer, review
and relationship metadata. Origins remain in evidence, notices, current reviews
or transfers, so both full packets and compact MCP capsules retain the target.
Primary evidence order and every distinct range, quote and qualification remain.
Named validation `reported_status_evidence` may use the existing
`evidence_ref_field`/`evidence_ref_indices` convention; annotations remain attached.
A missing `read_path` defaults to `path`; only identical duplicate paths may be
omitted, never a different extraction/HTML branch.

In compact MCP capsules, resolve the same packet-root JSON Pointer, then follow
the target source view's `source_fetch_id` or `fetch_id`. Source fetch retains
the complete original selector and annotations; pointer reuse changes neither
source identity nor statement support.

For an explicitly identified public path-portability derivative, use the existing
source-index entry with its actual public path/hash/bytes and `kind` set to
`public_path_portability_derivative`; `original_path` is a repository-relative
original identity and `original_sha256` its full hash. Originals stay privately
frozen. Those provenance locations are never opened. Current support must bind
the actual public derivative. An older immutable unit/review may show an explicit
public-copy route only when this exact original identity is declared and its old
quoted scientific range still validates there. Both source identities remain
visible; this neither asserts old full-byte availability nor confers acceptance.
Missing current support, undeclared historical support, wrong hashes, changed
quotations and ambiguous copy mappings fail ingestion. Rebind actual new units
and current scoped reviews through the normal build/check path.

When a selected UTF-8 original needs resource-locator portability, use
`python3 -m knowledge.source_portability RAW NEW_PUBLIC_DERIVATIVE` (or its
`portable_source` function in the curator's byte-mapping script). It leaves
originals and existing outputs intact and emits the existing hash/replacement
metadata. Register the result in the same source index above. Relative source
links and scientific slash notation such as `gates/workspace` are preserved;
do not apply a broad filesystem-prefix regex to scientific prose. A correction
to an exposed derivative gets a new route and immutable unit/review bindings;
retain the predecessor and identify its transport scope. This adds no producer
form, scientific review or automatic acceptance.

Before any public push, commit the reviewed candidate locally and run
`python3 state/check_current.py --base-revision <actual-PR-base-SHA> --preflight-only`.
This checks unchanged historical evidence and newly added literal local-source
locators before a draft can expose them. It does not run the full suite or
accept science. The existing full current-base gate and actual source-use
verification remain required before merge; producer research continues.

The same build now generates the small `knowledge/current/release.json`.
Published-mode plugin servers check that public input identity on requests
(cached checks expire after30 seconds), stage a separate immutable Git snapshot,
and validate every declared input/output hash and discovery membership before
switching readers. No scheduled automation, producer form or private database
is required. Cards, units, revised sources, accepted subresults and corrections
all reach this release through the same ordinary build/check/merge path.
An inaccessible or invalid new release produces an explicit stale/refresh
failure, not results labelled current from an old corpus. Old handles retain
their exact snapshot and point to current correction contexts before reuse.
After merge, verify actual installed search, all fetch continuation pages and
the decisive governing passage against the published input version; CLI and
Pages alone are insufficient. A change to runtime reader code requires the
reviewed runtime deployment, rather than silently parsing it with older code.

The release also declares the source context layout automatically. In the
linked layout, a source response preserves its exact passage, artifact selector
and every citing record's version/notice count/current-capsule route. Before
reusing a result, fetch that result's current capsule and every continuation:
its complete conditions, corrections, gaps and scoped review remain there.
Same-artifact citation context is navigation, not a transfer. Older releases
retain their original inline source payloads and handle bytes. Curators add no
layout fields or source notices by hand; the ordinary build/check sets this
snapshot format along with the release.

## Current consumer authority

An existing explicit standing human acceptance can have a curator-owned
`current_consumer_projection` notice. It names the existing `authority_notice_id`
and optional `consumer_views`, each with the exact accepted subject/content
version, a scoped current statement and the full scientific contract. This is
not another acceptance or audit. Preserve the original acceptance notice,
checkpoint card/status, source bytes and genuinely open scientific conditions.
Do not remove qualification by matching words such as "unreviewed".

The same build validates the authority, actual support and exact versions, then
generates `current_acceptance` and, where explicitly supplied, `current_consumer`
in the canonical record. The source-reported contract/content identity stays
unchanged. CLI, web, operation previews and current MCP capsules use the same
current consumer contract; original assessments remain at history/source routes.
Unknown authority, a stale subject, incomplete support or conflicting current
contracts fails ingestion. Context-only and unaccepted subjects do not inherit
acceptance. This is an intake-curator exception route, not a producer form or a
requirement to restate every result.

The release's `consumer_view_layout` marker selects compact current-capsule
links in new interface navigation. Old snapshots without that marker keep their
original routes and payload bytes under a newer reader. Changing this runtime
requires reviewed deployment; a data-only intake uses the ordinary refresh path.

If a checkpoint-pinned catalog transcribed an output as an input, a curator can
add a `source_input_contract_correction` semantic notice. It names the exact
`subject` id/content version, `field: requires`, corrected `value`, explanation
and actual `source_refs` with path/hash/lines/quote. The ordinary build derives
only that current input field and preserves the pinned catalog, original
contract, statement, conditions, output, scientific identity and review. It
does not confer acceptance. Missing support, stale versions, conflicting
corrections or another current consumer view fail ingestion. A changed
scientific claim uses an immutable scientific revision, rather than this
input-transcription exception. This remains curator work, not a producer form.

Published readers also support ordinary partial Git clones. Refresh inventories only the selected missing blob identities and fetches them together from the existing validated origin, without changing refs or FETCH_HEAD. The complete committed index is checked without fetching unselected blob contents; every selected source/view still undergoes normal full validation before activation. Independent copied files receive a private staging stat refresh before later read-only snapshot checks. Failed owned stages remain quarantined for diagnosis; they are never registered as served versions. This is part of the same automatic intake path, with no new source metadata, job, key or configuration. Reader-code changes still require reviewed deployment.
